# 05 · 锦鲤 · 彩票预测插件（dsh-koi）

让 dsh 里的第二个 agent「锦鲤」在每个开奖日 **17:30 左右**研究历史走势后出号，QQ 私聊推送给主人；开奖后自动对账、按官方奖级拆注判定、记一份诚实的模拟账本。

> 定位先说死：彩票每期都是独立随机事件，任何算法都不改变中奖概率。这个插件卖的是「有人认真研究过 + 按时送达 + 诚实记账」，账本会难看，难看是它的功能不是 bug。

## 需求是怎么定的（2026-10-23 与主人逐条确认）

| 项 | 决定 |
| --- | --- |
| 出号方式 | **AI 全程**：唤醒 agent 研究官方历史数据 → 自己挑号 → 写完整分析（不是纯算法随机） |
| 推送 | QQ **私聊**管理员 1017099872（走 NapCat HTTP API，不动 dsh-onebot 插件） |
| 时间 | 开奖日 **17:30** 出号（18:10 后补跑的标「晚到」，19:50 放弃并致歉） |
| 双色球 | 复式 **红8+蓝1** = 28 注 56 元/期（周二/四/日） |
| 大乐透 | 复式 **前7+后2** = 21 注 42 元/期（周一/三/六） |
| 排列三 | **直选一注** 2 元/期（每天） |
| 对账 | 22:00 起自动抓开奖 → 拆注判奖 → **模拟账本**（若每期都买：投入/中奖/净额） |
| 面板 | 只做「**现在来一注**」按钮（不做设置页/历史页，配置在服务器文件里改） |
| 人设 | 元气小财迷，名字「锦鲤」 |

## 数据源（2026-10-23 实测全通）

| 彩种 | 来源 | 备注 |
| --- | --- | --- |
| 双色球 | 福彩官网 `cwl.gov.cn` findDrawNotice | 自带每期各奖级单注奖金 ✓（对账直接用） |
| 大乐透 | 体彩 `webapi.sporttery.cn` gameNo=85 | **必须带浏览器头**（Referer/Origin/UA），否则回验证页 |
| 排列三 | 体彩 gameNo=350133（排列五）**取前三位** | 排列三/排列五同机同期摇号，前三位即排列三 ✓ |

## 架构

```
调度器（dsh 进程内，每 30s tick，状态机落盘）
  ├─ 17:30 抓官方历史 → 打包数据 → sessionController 唤醒「锦鲤」会话
  │        ↓ 她写结构化 JSON 文件（文件契约，不解析自由文本）
  │   validatePicks 硬校验 → 不过打回重写一次 → 再不行随机兜底
  │        ↓
  │   NapCat HTTP /send_private_msg → 私聊主人
  ├─ 22:00 轮询官方开奖 → 复式拆注按官方奖级判 → 记 ledger.json → 推战果
  └─ 面板「现在来一注」→ 同一条流水线，标「加餐」（不记账）
```

设计上的三道保险：① AI 产出走**文件契约 + 硬校验**，格式不对重写、再不行兜底随机号，18:00 前一定有消息；② 出号/推送/对账状态全落盘，**重启不乱**；③ agent 运行全局串行，正式预测和加餐不撞车。

装完验收五步（v1.1 起从三步扩为五步）：

1. 面板「设置 → 彩票」→ 点「**测试推送**」→ 手机收到 = NapCat 通道通 ✓
2. 点某彩种「**现在来一注**」→ 等 1–4 分钟 → 面板显示她的完整分析 + 手机收到加餐私聊 ✓
3. 当晚 22:00 后收到战果私聊、`node tools/koi.mjs ledger` 有账 ✓
4. **杀 NapCat 跑一期**：`docker stop napcat` 后等一期出号（17:30–19:50 窗口内）→ 面板出现「未送达」红标；`docker start napcat` 后通道恢复，预测推送按 5 分钟间隔重试、超 19:50 终止线转补发队列，恢复后 2 个重试周期内收到带【补发】标注的消息 ✓
5. **对账中途重启**：22:00–23:30 对账窗口内 `systemctl restart dsh` → 当晚战果正常补完、`ledger` 该期只有一条账（不重复记账）✓

## 配置（改 `/home/dsh/.dsh/koi.config.json`，下一轮 tick 生效，不用重启）

```jsonc
{
  "push": { "target": "1017099872", "napcatHttp": "http://127.0.0.1:3000", "retryMinutes": 5 },
  "time": { "predictAt": "17:30", "catchUpEnd": "19:50", "settleAt": "22:00", "settleGiveUp": "23:30" },
  "games": { "ssq": { "enabled": true }, "dlt": { "enabled": true }, "p3": { "enabled": true } },
  "historyCount": 30,
  "historyTail": 10,
  "persona": "",          // 留空用内置「元气小财迷」；想改就整段人设写进来
  "holidays": [],         // v1.1：休市日期 ["YYYY-MM-DD"]，命中日不出号、不对账、不致歉，静默顺延
  "mind": { "enabled": false }   // v1.1 预留：认知层总开关（dsh-koi-mind 未部署前保持 false，面板 status 可见）
}
```

> v1.1 新键说明：`push.retryMinutes` = 推送失败重试间隔（分钟，默认 5；预测重试至 19:50、战果/致歉至 23:30，超线转补发队列、恢复后带【补发】补发）；`holidays` = 休市日历；`mind.enabled` = 认知层总开关（默认 false，纯 v1.1 行为）。旧配置文件缺这三个键也能跑，全部走代码内默认值。

## 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 收不到私聊，面板显示「推送通道：不通」 | NapCat 容器挂了 / 掉线 | `docker restart napcat`；掉线退回扫码（见 04 文档） |
| 面板显示「她正在研究…」很久 | agent 会话卡住 | 看 `journalctl -u dsh -n 100 \| grep koi`；重启 dsh 后状态机会重试 |
| 预测消息标了「兜底号」 | AI 两次产出都不合规 | 看日志里第一次的报错原因；通常是模型抽风，下一期自愈 |
| 战果没来 | 开奖公布晚于 23:30 | 次日 22:00 会自动补账；急用 `settle --push` 手工补 |
| 体彩数据抓不到 | 服务器出口被体彩接口拦 | 重试即可（调度器自己会重试 3 次）；持续失败看 `deps` 输出 |
| 想停掉某个彩种 | — | `koi.config.json` 里 `games.<key>.enabled=false` |

## 已知边界（v1 明确不做）

- **不加餐记账**：面板加餐出的号不进账本（口径 = 「只买每期正式预测」），消息里会标「加餐不记账」
- **浮动奖**：一/二等奖金额官方次日才公布；当晚战果里标「含浮动奖」，金额按 0 计、注数照报（28/21 注复式中一二等概率极低，不影响日常账本）
- **桌面版不适配**：只跑服务器（桌面 Electron 里进程内抓数/推送没验证过）
- **排列三只有直选**：组选/和值玩法没做（主人只买直选）
