## 2. 冻结区（Frozen Zones）

> 冻结 = v2 认知层与任何迭代**不得修改语义**；改动必须 minor 版本 +1、全量回归、更新本文档。

| # | 冻结对象 | 为什么冻结 |
| --- | --- | --- |
| FZ-1 | `draws.js` 的 `judge` / `enumerateBets` / `stakesOf` / `comb` | 账本正确性的根；判奖语义一动，历史账与未来账不可比 |
| FZ-2 | `draws.js` 的 `validatePicks` / `randomPicks` | 防垃圾号闸门；放宽校验 = 三道保险失效 |
| FZ-3 | 数据文件路径布局与三 JSON 契约字段（§5.1） | 跨进程/跨插件共享地基；v2 只读依赖它 |
| FZ-4 | `push.mjs` 的 `assertLoopback` | 安全不变量：NapCat 3000 无 token，回环断言是最后一道墙 |
| FZ-5 | 调度器状态机相位与转移语义（`idle→predicted→settled / failed / skipped` + carry） | 重启恢复与「重启不乱」承诺依赖其确定性；v2 只在出号流水线内部挂钩子，不动相位机 |
| FZ-6 | 4 条面板 API 的既有请求/响应形状（§5.3） | 已发布契约；只允许加字段，不允许改/删 |

**解冻流程**：提变更 → 说明为何必须动冻结区 → `node --test` 全过 + 验收五步 → 版本 minor+1 → 更新本文档表格。

## 5. 接口契约

### 5.1 数据文件契约（FZ-3，v1.0 实测字段）

**koi.config.json**（用户可改；每 tick 现读）

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `push.target` | string | `'1017099872'` | 接收私聊 QQ 号 |
| `push.napcatHttp` | string | `http://127.0.0.1:3000` | 必须回环（代码强制） |
| `time.predictAt` / `catchUpEnd` / `settleAt` / `settleGiveUp` | `'HH:MM'` | 17:30 / 19:50 / 22:00 / 23:30 | 出号窗口与对账窗口 |
| `games.ssq/dlt/p3.enabled` | bool | true | 彩种开关 |
| `historyCount` / `historyTail` | number | 30 / 10 | 注入历史期数 / 流水明细期数 |
| `persona` | string | `''` | 空=内置「元气小财迷」 |
| `holidays` ⚠C2 | string[] | （v1.1 预留） | 休市日期 `YYYY-MM-DD` |

**state.json**（调度器独占写；当日状态机，重启恢复依据）

| 字段 | 说明 |
| --- | --- |
| `date` | 状态所属日 `YYYY-MM-DD`；跨天重建并生成 carry |
| `games.<key>.phase` | `idle → predicted → settled`；异常终态 `failed`（3 次尝试全败）/ `skipped`（过窗未出） |
| `games.<key>.{attempts,lastAttemptAt,lastError}` | 出号尝试计数与错误 |
| `games.<key>.{issue,via,message,picksLine}` | 出号产物；`via = 'ai' \| 'fallback'` |
| `games.<key>.{pushTryAt,pushedAt,pushErr}` | 推送重试游标与结果 |
| `games.<key>.{settled,settleTries,nextSettleAt,apologyPushed}` | 对账轮次控制 |
| `carry` | `[{date, gameKey}]` 跨天待对账清单（⚠ C8 扩范围） |
| `lastError` | tick 级异常备忘（面板显示） |

**predictions.json**（预测流水 + 对账结果回填；v2 预测档案前身）

| 字段 | 阶段 | 说明 |
| --- | --- | --- |
| `at` / `kind` / `game` / `issue` / `date` | 出号时 | `kind: 'daily' \| 'quickpick'` |
| `picks` / `via` / `bets` / `cost` / `spec` | 出号时 | 号、来源、注数、投注额、规格文案 |
| `settled` / `result` / `prize` / `grades` / `pushedResult` / `settleNote` | 对账时回填 | `result` 为官方开奖对象；⚠ v2 起本文件转 append-only，回填字段迁 SQLite |
| `schemaVersion` ⚠C4 | 顶层 | `1` |

**ledger.json**（唯一记分口径）

| 字段 | 说明 |
| --- | --- |
| `entries[].{at,kind,game,issue,date,cost,prize,bets,grades}` | 每期一行；`grades: {奖级:注数}`；⚠ C1 后 `prize` 可为 `null`（放弃待补） |
| `schemaVersion` ⚠C4 | 顶层 `1` |

**会话工作目录契约**（调度器 ⇆ 锦鲤会话的交换场）
`predict-<game>-<YYYY-MM-DD>.json`（加餐为 `predict-<game>-qp-<stamp>.json`）。生命周期：调度器预删 → 会话写入（≤4 分钟）→ 调度器轮询读取（3s 间隔）→ 校验后**必删**。

### 5.2 picks JSON 契约（给 AI 的交卷 schema，随唤醒提示词下发）

```jsonc
// 双色球                                    // 大乐透                                  // 排列三
{ "issue": "2026122",                       { "issue": "26121",                        { "issue": "26285",
  "picks": { "red": [8个1–33不重复整数],      "picks": { "front": [7个1–35],             "picks": { "digits": [3个0–9] },
             "blue": 1个1–16整数 },                     "back": [2个1–12] },                       "message": "…" }
  "message": "给主人的完整正文" }                       "message": "…" }
```
校验规则（`validatePicks`，FZ-2）：个数/去重/范围/整数全过才算合法；`raw.picks ?? raw` 双形态容忍；红/前区自动排序规范化。v1.1 起顶层加 `"schemaVersion": 1`（C4）。

### 5.3 面板 HTTP API 契约（FZ-6）

| 路由 | 方法 | 入参 | 出参（成功） | 错误 |
| --- | --- | --- | --- | --- |
| `/dsh-koi/api/status` | GET | — | `{ok, today, calendar, allGames[], games{<key>:{enabledToday,phase,issue,picksLine,via,pushedAt,pushErr,settled,lastError,spec}}, carry, ledger, ledgerText, push:{ok,detail}, pushTargetMasked, scheduler, configPath, lastError}` | 200 永返（ok:false 表异常）；403 非回环 |
| `/dsh-koi/api/quickpick` | POST | `{game}` | `{ok:true, id}` | 400 `{ok:false,error}`（彩种不存在/已关/会话忙）；405 |
| `/dsh-koi/api/quickpick?id=` | GET | id | `{ok:true, job:{id,game,status:'running'|'done'|'push-failed'|'error',message,picksLine,via,error,startedAt,doneAt}}` | 404 无此任务 |
| `/dsh-koi/api/test-push` | POST | — | `{ok, detail}` | 405；失败也在 200 里 `{ok:false,detail}` |

安全（全部路由）：回环 Host + `connection.requestRejection` 信任栅栏，任一不可用 503 fail-closed。

### 5.4 NapCat API 契约

| 端点 | 请求 | 成功判定 | 用途 |
| --- | --- | --- | --- |
| `POST /send_private_msg` | `{user_id:number, message:string}` | `retcode===0 \|\| status==='ok'` | 预测/战果/致歉/加餐私聊 |
| `POST /get_login_info` | `{}` | `retcode===0 && data.user_id` | deps 体检、面板通道探测 |

### 5.5 DSH inject API 契约（最小依赖面）

| 注入项 | 用到的面 | 不碰的面 |
| --- | --- | --- |
| `sessionController` | `create({sessionId,cwd})`、`prompt({requestId,sessionId,mode:'queue',content}, signal)` | 其余一切（工具授权、记忆等由宿主全局配置） |

### 5.6 CLI 契约（tools/koi.mjs）

`history <game> [--count N] [--show M]` / `validate <game> <json|@file>` / `settle [--date YYYY-MM-DD] [--push]` ⚠C1 加 `--force` / `ledger [--reset]` / `push --text "…"` / `deps [--json]` / `demo-predict [game]`。路径解析与宿主一致（`DSH_HOME` 优先、`KOI_CONFIG` 覆盖）。

### 5.7 （v2.0 预留）SQLite 表结构（koi-mind 独占写）

## 6. schema 演进规则（冻结区 FZ-3 的配套）

1. **只加不改不删**：新字段必须可缺省，旧读取方遇到未知字段必须忽略；
2. 顶层 `schemaVersion` 单调递增；读取方对高版本文件「可读则读，不可读则报错拒绝写」；
3. 破坏性变更 = 版本 minor+1 + `tools/` 提供迁移命令 + 更新本文档；
4. predictions.json 在 v1 内保持「回填」模式；**v2 迁 SQLite 后立即转为 append-only**（自举纪律 1 的载体切换）。
