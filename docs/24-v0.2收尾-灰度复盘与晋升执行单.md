### 3.1 G-4 细化：为什么没有 qq.js 就不能晋升

1. `migrate-v2` 会把 v1 的 `push.target` / `push.napcatHttp` 迁到侧车 `koi/channels/qq.config.json`，并在主配置 `channels` 里注册 `{type:"qq", enabled:true}`（**本轮实测**，见 §4-G6 输出）。
2. 渠道层对缺失适配器的处理是 `status: missing` + 明确报错，**不会回退到旧的 push.mjs**（市场版已无此文件）。
3. 结果是：晋升后出号/对账一切正常，但**QQ 私聊一条也发不出去**，且事件状态会一直是 retrying/failed——比「没升级」更糟。
4. 因此晋升顺序必须是：**先落 qq.js 与侧车，再切代码、再迁移**；或至少在切代码后立刻补 qq.js 并重启。

### 3.2 G-6 证据（本地 v1 夹具演练，2026-11-16）

用 docs/05 的 v1 配置模板（`schemaVersion:1`、`push.target/napcatHttp`、三彩种 `games.enabled=true`）在临时 `DSH_HOME` 上执行：

```
migrate-v2 --dry-run  → exit 0，报告：凭证→qq.config.json 侧车、注册 qq 渠道、
                        retryMinutes→time、games.ssq/dlt/p3 → modes.*=auto、
                        weeklyCap=10000000、业务 JSON 零触碰；dry-run 不落盘（配置仍 schemaVersion 1）
migrate-v2            → exit 0，配置升 schemaVersion 2；sidecar 内容 {target, napcatHttp} 正确；
                        channels=panel:true, qq:true；games/push 字段已清；modes 全 auto
migrate-v2（复跑）     → exit 0，「幂等：配置未改动（重跑无 diff）」
```

结论：迁移语义与 docs/16 D-006、ADR-0006 一致；**生产是 v1 配置，此路径就是晋升当天要走的路径**，已预演通过。

## 5. 晋升执行单（服务器侧，按序执行）

> 约定：`APP=/opt/dsh-plugins/dsh-koi`、`CANARY=/opt/dsh-plugins/dsh-koi-canary`、`HOME_DIR=/home/dsh/.dsh`、`STAMP=$(date +%Y%m%d-%H%M%S)`。
> 所有 `node` 命令以 dsh 用户执行（`sudo -u dsh -H`），保证读写的是 `/home/dsh/.dsh`。

### 步骤 0 · 前置检查

```bash
systemctl is-active dsh                                   # active
ss -ltnp | grep -E '3080|3081'                            # 只应看到 3080；3081 若仍在跑先停
sudo -u dsh -H bash -lc "curl -s -X POST http://127.0.0.1:3000/get_login_info -d '{}'"   # retcode 0 + user_id=983605373
node -v && cat $CANARY/package.json | grep '"version"'    # v24.x；0.4.1
```

### 步骤 1 · 全量备份（代码 + 数据 + 配置）

```bash
install -d -o dsh -g dsh /opt/dsh-plugins/_backup
cp -a $APP /opt/dsh-plugins/_backup/koi-app-$STAMP
cp -a $HOME_DIR/koi /opt/dsh-plugins/_backup/koi-data-$STAMP
cp -a $HOME_DIR/koi.config.json /opt/dsh-plugins/_backup/koi.config-$STAMP.json
ls -ld /opt/dsh-plugins/_backup/*$STAMP*
```

### 步骤 2 · 先落私有 QQ 适配器（G-4）

```bash
install -d -o dsh -g dsh $HOME_DIR/koi/channels
install -o dsh -g dsh -m 0644 /tmp/qq.js $HOME_DIR/koi/channels/qq.js    # 由本机 deploy/koi-channels/qq.js 上传
```

侧车 `qq.config.json` 由步骤 4 的 `migrate-v2` 自动生成（内容取自 v1 的 push 段）；若届时未生成，手工写入：

```bash
sudo -u dsh -H tee $HOME_DIR/koi/channels/qq.config.json >/dev/null <<'JSON'
{ "target": "1017099872", "napcatHttp": "http://127.0.0.1:3000" }
JSON
```

### 步骤 3 · 切换代码

```bash
systemctl stop dsh
mv $APP /opt/dsh-plugins/dsh-koi.old-$STAMP
cp -a $CANARY $APP
chown -R dsh:dsh $APP
sed -i 's/\r$//' $APP/lib/*.js $APP/tools/*.mjs
systemctl start dsh
sleep 3; systemctl is-active dsh
journalctl -u dsh -n 80 --no-pager | grep -E '锦鲤生物钟|koi' | tail -5
```

### 步骤 4 · 配置迁移（v1 → v2，先 dry-run）

```bash
sudo -u dsh -H bash -lc "cd $APP && node tools/koi.mjs migrate-v2 --dry-run"
sudo -u dsh -H bash -lc "cd $APP && node tools/koi.mjs migrate-v2"
```

期望输出（本轮已演练，逐条应对上）：凭证→侧车、注册 qq 渠道、games→modes=auto、`weeklyCap=10000000`、业务 JSON 零触碰、`✓ 配置已升 schemaVersion 2`。

### 步骤 5 · 自检

```bash
sudo -u dsh -H bash -lc "cd $APP && node tools/koi.mjs deps"       # 数据源全 ✓；渠道段 panel=ok、qq=ok（缺适配器会显示 missing）
sudo -u dsh -H bash -lc "cd $APP && node tools/koi.mjs selftest"   # 12 pass / 0 fail
sudo -u dsh -H bash -lc "cd $APP && node tools/koi.mjs ledger"     # 历史账目仍在
sudo -u dsh -H bash -lc "cd $APP && node tools/koi.mjs channels"   # 渠道与掩码凭证
```

### 步骤 6 · 面板验收（浏览器，五步验收的 1/2 步）

1. 「设置 → 彩票」能打开（浏览器加载链未断）。
2. 渠道行：panel + qq 均绿，QQ 目标显示为掩码（`101****72`）。
3. 点「测试推送」→ 手机收到 = 全链路通。
4. 点某彩种「现在来一注」→ 1–4 分钟内出 AI 号码 + 手机收到。

### 步骤 7 · 收尾

```bash
# 确认灰度实例已停、旧目录保留一周后再删
ps -eo pid,cmd | grep 'dsh web' | grep 3081 || echo '3081 已停'
# 记录晋升结果到 docs/24 §7 与 docs/23 §5；发 tag
git tag -a v0.4.1 -m 'koi v0.2 重构版晋升生产'
```
