## 二、定位对齐：试验田与诚实条款

你说「与其说是写了个彩票插件，不如说是 AGI 探索架构上搭了个彩票摸索机制」——我完全同意这个定位，并且认为**彩票是 AGI 自我进化最诚实的试验田**，理由：

1. **真值客观**：每期开奖号码公开、即时、不可辩驳，架构是否「真的在改进」无法自欺；
2. **节奏固定**：双色球每周 3 期、大乐透 3 期、排列三每天，反馈循环天然高频；
3. **数据完备**：历史全量数据公开可爬（双色球 2003 年起 3400+ 期，大乐透 2007 年起 2400+ 期，排列三 2004 年起 7000+ 期）。

同时把丑话说在前面，并把它变成架构的一部分（这正是你说的「自举纪律」）：

> **诚实条款**：每期开奖是独立随机事件，任何技巧、任何多 Agent 博弈都不会提高中奖概率。因此本项目的成功指标分两层——**架构指标**（流程稳定、知识飞轮运转、复盘按期产出、记忆可回溯）是我们要挣的；**预测指标**（命中率）只作为与「随机基线」对照的观测值，**中奖不是 KPI**。账本难看是功能不是 bug，v1 文档里这句话继续有效。

**自举纪律五条（写死在架构里，防止系统学会自欺）：**

1. **预注册**：预测号码+完整理由在开奖前落盘、只追加不可改；
2. **随机基线同行**：每期同时生成一注纯随机对照号，所有策略的战绩永远连同基线一起上报；
3. **无事后选择**：复盘只针对事前登记过的假设；事后发现的「规律」一律标注「探索性」，必须在未来 N 期样本外验证通过才能晋升；
4. **兜底透明**：随机兜底的号永远在消息里如实标注；
5. **账本诚实**：ledger 是唯一记分口径，不允许选择性汇报。

## 三、总体架构：执行层 + 认知层

```
┌────────────────────────── 认知层（新增：dsh-koi-mind）──────────────────────────┐
│  数据仓库        知识宫殿            因子库           复盘引擎        语义时空图   │
│  (全量历史+     (技巧卡片+          (可计算的        (周报/月报/     (号码×期号× │
│   预测档案)      网络学习沉淀)        技巧+回测档案)    归因分析)       因子×事件)  │
└───────────────┬──────────────────────────────────────────────────┬────────────┘
                │  文件契约 + SQLite 共享（不侵入 v1 代码）            │
┌───────────────┴────────────── 执行层（dsh-koi v1，保持稳定）─────────┴────────────┐
│  调度器(17:30出号/22:00对账) → 记忆注入 → 多Agent博弈 → 硬校验 → QQ推送 → 账本    │
└──────────────────────────────────────────────────────────────────────────────┘
```

**每期完整时间线（认知层加入后）：**

| 时间 | 动作 | 涉及能力 |
| --- | --- | --- |
| 开奖日 17:30 | 从记忆宫殿注入：往期同类局势、相关因子近期表现、既往教训 | 元认知 |
| 17:30 | 数据官从数据仓库打包统计 → 各策略 Agent 独立提案 → 互评质询 → 修订 → 主持人合成定稿 | 多 Agent 博弈 |
| 17:50 前 | 硬校验（v1 三道保险原样保留）→ 私聊推送，附完整分析+引用的因子+置信度 | 预注册 |
| 22:00 | 对账拆注判奖 → 归因（哪些因子押中了哪些位）→ 全部写入预测档案 | 反馈闭环 |
| 每周日晚 | 周报：各策略/因子战绩 vs 随机基线、分析质量自评、下周计划 | 元认知 |
| 每月末 | 月报：因子晋升/降级/淘汰，知识卡片更新，方法论修订 | 知识飞轮 |

**关键设计决策：认知层是独立插件 `dsh-koi-mind`，不塞进 dsh-koi 里。** 好处：v1 稳定不动、认知层可以激进迭代、两者通过数据文件解耦。

> **2026-10-25 修订**：认知层的定位由「自建全套能力」改为「**编排层 + 领域件**」——凡有现成插件的能力一律整合、不重造轮子，详见第九节《整合优先原则》。

## 四、四大能力 → 具体机制映射

### 4.1 元认知（自我认知循环）

- **预测档案**（海马体）：每期记录号码、完整推理文本、引用的技巧/因子 ID、置信度、当期局势快照——开奖后追加结果与奖级，永不改写；
- **复盘报告**：周报自动生成，含「各策略 vs 随机基线」「分析纪律自评（是否违反五条纪律）」「本周期最值得记住的一课」；
- **记忆注入**：出号会话启动前，自动检索档案中「历史相似局势」「该因子近 30 期表现」「既往同类错误」，合成上下文注入——参考 dsh-auto-memory 的「主动注入，不靠模型自己想起来查」。

### 4.2 持续学习（知识飞轮）

你上传的书籍/技巧、我从网络学来的知识，走同一条流水线：

```
原始材料(PDF/TXT/网页) → 技巧卡片(结构化:名称/出处/适用彩种/具体规则/可否计算)
     → 可计算的卡片 → 因子化(写成回测代码) → 全量历史回测 → 因子档案
     → 样本外观察期 → 晋升/降级/淘汰(月报执行) → 因子库版本化
```

- 技巧卡片入库即触发回测，回测结论（含「与随机无异」的结论）写回卡片——**学到≠有用，回测过才算数**；
- 网络学习：定时任务抓取彩票门户的走势/资讯页 → LLM 提炼候选技巧 → 进同一条流水线（版权注意：只提炼方法不搬运原文）。

### 4.3 世界模型（条件空间 + 语义时空图）

- **条件空间**：三个彩种的号码空间形式化（双色球 红C(33,6)×蓝16 / 大乐透 前C(35,5)×后C(12,2) / 排列三 1000），加上状态变量（遗漏、和值、奇偶比、012路、AC值等派生统计量）——这是因子回测的数学地基；
- **语义时空图**：SQLite 图表起步（2核2G 跑不动 Neo4j）：节点 = 号码 / 期号 / 因子 / 技巧卡片 / 特殊事件，边 = 出现于 / 触发 / 支持 / 反对 / 时序相邻。先服务检索（「蓝球 07 遗漏 20+ 时期大家怎么说」），面板可视化放最后。

### 4.4 自我改进（自举纪律）

见第二节五条纪律——它们不是口号，是代码级不变量：预注册表 append-only、随机基线由独立代码路径生成、晋升规则只有月报的固定流水线有权执行。

## 七、需要你拍板的问题（13 道）

### Q1. dsh-koi v1 现在就部署上线吗？
**背景**：代码已就绪，部署命令写在 `docs/05-锦鲤预测.md`。每晚一天，预测档案和账本就少积累一天——记忆宫殿的地基是数据，越早上越好。
**选项**：A. 现在（我下轮就传服务器） / B. 等认知层一起上 / C. 先看看再说
**我的建议**：A。认知层是增量，不影响 v1。
**答复**：**先打 v1.1 修复包再部署**（2026-10-24 需求引出会话拍板；阶段A于同日回填，原讨论会话不可检索，记录源=docs/12 §5.1）。⚠ 与本文档建议（A 立即部署）不同：采 docs/10 建议，先修 BUG-K1 漏账再上线（M0 时点 = v1.1 回归通过日，docs/12 FR-010）。

### Q2. 历史数据：全量爬取的方案可以吗？你手里还有别的数据吗？
**背景**：我计划从官方源把三个彩种历史一次性拉全（共约 1.3 万期，SQLite 存放约几 MB），之后每期开奖增量同步。官网接口已实测可用。
**选项**：A. 官方源全量爬（建议） / B. 你先把你手里的数据给我一份对一下口径 / C. A+B 双保险
**我的建议**：A，爬完把统计口径（期号格式、字段落库规则）发你过目；你手里如有特殊数据（如奖池、销量、地区数据）随时给，都是「语义时空图」的好原料。
**答复**：**A 官方源全量爬**（2026-10-24 拍板，回填来源=docs/12 §5.1）；口径核对报告经主人确认归档（docs/12 FR-011/AC-004）。

### Q3. 记忆宫殿选型：auto-memory 还是 prime-memory？
**背景**：两者都是 DSH 原生插件且不冲突安装会打架（都往上下文注入记忆）。auto-memory 胜在主动注入+零依赖+轻（适合 2G 机器）；prime-memory 胜在四层蒸馏+图谱投影（更贴「记忆宫殿」形态，但更吃资源）。
**选项**：A. auto-memory 起步（建议） / B. prime-memory 起步 / C. 两个都装实测对比一周再定
**我的建议**：A。先把闭环跑起来，M4 阶段如需图谱蒸馏再切换。
**答复**：**A auto-memory 起步**（2026-10-24 拍板，回填来源=docs/12 §5.1）；koi 出号会话默认关闭其宿主级自动注入，统一走认知层注入模板（docs/12 FR-028）。

### Q4. 知识宫殿：自建轻量还是上 WeKnora？
**背景**：你的 2核2G 服务器装不下 WeKnora 标准版。自建轻量 = 技巧卡片（Markdown）+ SQLite 全文检索 + 因子库，全部文件可读可改；WeKnora 功能全但需要独立机器。
**选项**：A. 自建轻量起步（建议） / B. 现在就想上 WeKnora（需加机器） / C. A 起步，将来换大机器再迁 WeKnora
**我的建议**：A（或 C）。书籍你直接扔给我 PDF/EPUB/MD 都行，我来解析拆卡片。
**答复**：**A 自建轻量起步**（2026-10-24 拍板，回填来源=docs/12 §5.1）。

### Q5. 多 Agent 博弈：内部编排还是 DeepSeek-Bot 常驻群聊？
**背景**：内部编排 = 每期开奖日临时拉会、开完散会，省 token、流程可控、全记录落盘；DeepSeek-Bot = 常驻 bot 群聊，可以在「沉睡森林公会」公开上演博弈过程（观赏性强，但 token 消耗大、私聊内容曝光）。
**选项**：A. 内部编排起步（建议） / B. 上 DeepSeek-Bot，群里公开博弈 / C. A 起步，另开一个「赛后点评」bot 在群里说话
**我的建议**：A 或 C。C 折中：博弈在后台进行，群里只看最终点评。
**答复**：**A 内部编排**（2026-10-24 拍板，回填来源=docs/12 §5.1）；博弈全记录落盘、不进群聊、私聊分析不曝光（docs/12 FR-016）。

### Q6. 博弈规模与 token 预算
**背景**：三彩种每周约 13 期。内部编排的消耗估算：轻量（3 角色×1 轮）≈ 每期 2–4 万 token；标准（5 角色×2 轮辩论）≈ 每期 5–10 万。每周约 70–130 万 token（标准档）。
**选项**：A. 轻量档 / B. 标准档（建议） / C. 只在双色球和大乐透用标准档，排列三走轻量档
**我的建议**：C。排列三每天一期，用轻量；大彩种隆重些。
**答复**：**C 混合档：双色球/大乐透=标准档、排列三=轻量档**（2026-10-24 拍板，回填来源=docs/12 §5.1；档位×彩种分配见 docs/12 FR-017）。

### Q7. 模型配置：现在 DSH 用的是什么模型？分工用不用分级？
**背景**：出号（主力推理）、技巧蒸馏、周报复盘对模型要求不同。可主力用强模型、蒸馏/对账用便宜模型。
**选项**：A. 全部用现在的模型不动 / B. 你告诉我可用模型清单，我做分级路由（建议） / C. 只要便宜优先
**我的建议**：B，告诉我你 DeepSeek/GLM 的 Key 支持哪些模型。
**答复**：**A 不分级，全部用 DSH 现状模型**（2026-10-24 拍板；阶段A回填，记录源=docs/12 §5.1）。⚠ 与本文档建议（B 分级路由）不同；token 控制杠杆 = 角色数×轮数 + 预算硬顶（docs/12 BC-013）。

### Q8. 网络学习：学哪些站？什么频率？
**背景**：计划每周一次抓取主流彩票门户的走势/资讯页提炼技巧。有些站防爬严，爬不到的我会来要数据。
**选项**：A. 你有指定要学的网站吗？（列给我） / B. 我自己选 2–3 个主流站试爬（建议） / C. 网络学习先不做，只靠你上传的书籍
**我的建议**：B，首月先试跑，爬不动的网站清单发你。
**答复**：**B 自选 2–3 个主流站周更**（2026-10-24 拍板，回填来源=docs/12 §5.1）；站点白名单变更只能经代码版本变更生效（docs/12 FR-044/BC-015）。

### Q9. 语义时空图的存储形态
**背景**：SQLite 图表（轻，够用） vs Neo4j（重，需升配）。

## 九、整合优先原则（2026-10-25 与主人讨论后补充）

主人提出：总是忍不住把现成插件的功能重写一遍是错的，应该**把插件整合进功能里，我们只管好对下游插件的输入**。采纳此原则，并细化为决策规则和整合地图。

### 决策三问（任何新功能先过一遍）

1. **市场里/已装插件有没有现成能力？** 有 → 整合，定义输入契约；
2. **整合后输出可读、失败可控吗？** 不可控 → 包一层薄适配器，仍然不重写；
3. **它是领域专属件或纪律不变量吗？** 是 → 自建（这是项目本体，不是轮子）。

### DSH 里整合的三个层级（由轻到重）

1. **工具级（零代码）**：装上插件，其 Agent 工具全局可用，锦鲤会话直接调用（auto-memory 注入与 memory_add、dsh-web-search、WeKnora 的 weknora_* 只读工具都属此类）；
2. **契约级**：通过文件/SQLite 与下游插件交换数据（如把每期档案摘要喂给记忆系统）；
3. **适配器级**：写薄薄一层转换代码对齐上游格式，仍不重写功能。

### 整合地图（v2 分工修订版）

| 能力 | 来源 | 整合方式 | 我们管什么 |
| --- | --- | --- | --- |
| 记忆宫殿 | dsh-auto-memory（或 prime-memory） | 工具级：装上即注入，锦鲤直接调 memory_add | **喂什么**：每期档案摘要、复盘结论的输入质量决定记忆质量 |
| 联网学习 | dsh-web-search（dsh-m 市场） | 工具级：零代码 | 学习任务提示词、站点白名单、提取纪律 |
| 知识库 RAG | WeKnora 官方 DSH 插件 | 换大机器后安装，会话直接用其只读工具 | 书籍入库管道、检索口径 |
| 多 bot 群聊 | DeepSeek-Bot | 仅当 Q5 选「群里公开博弈」才装 | 各 bot 人设、议程输入 |
| 彩票数据仓库 | **自建** | — | 全部（没有插件懂彩票数据） |
| 因子回测 + 预测档案 | **自建** | — | 全部（**自举纪律的写入路径必须自持**，不能委托第三方插件） |
| 每期编排 | DSH 原生 sessionController + 契约文件 | 粘合，非重写 | 议程、角色提示词、超时兜底 |

### 整合的三个代价（防矫枉过正）

1. **输入要管，输出也要管**：注入了什么、何时注入、失败时什么语义，都要在复盘里可解释；
2. **版本耦合**：上游插件升级可能改变行为，用 dsh-m 的 commit SHA 锁定 + 升级前跑回归验收；
3. **资源与冲突**：2核2G 是硬约束；两个记忆插件不可同装（注入冲突）。
