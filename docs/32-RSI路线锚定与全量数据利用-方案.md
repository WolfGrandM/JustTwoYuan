## §2 环 A · 假设自动生成环（推荐先行，不依赖 M3）

- **机制**：月报流水线新增「探索性提案」段——LLM 读全量数据的**聚合视图**（见 §6），提出 K 个候选假设；**每个假设必须写成可因子化的预注册形式**（factorize DSL 可执行），自动进观察期；后续月报按既有规则检验（样本外显著 + Bonferroni + 上限 2 + 90 天零观点淘汰 + 否决窗口），与卡片因子同一条流水线、零特权，晋升或淘汰都如实留档。
- **纪律定性**：这不是新纪律，是 BC-004「无事后选择」预留合法入口的自动化——「事后发现的规律标探索性、样本外通过才晋升」的通道，由 AI 自动填单。

## §6 全量数据利用设计（环 A 的技术地基）

### 6.1 核心原则：LLM 吃摘要，代码吃全量

全量历史（双色球 3400+ 期 / 大乐透 2400+ / 排列三 7000+，drawstore 本地底座 + backfill 回填）**永远不会整包进上下文**——上下文爆炸在架构上已防住，因为出号 agent 从设计起只见压缩产物：

```
全量数据（drawstore）──┬─ backtest.js（防前视切片）──▶ 因子档案（回测结论=全量的离线蒸馏）
                        ├─ attribution（每期在线判定）─▶ 归因记录（全量的在线消化）
                        ├─ stats.dataPack（窗口压缩）─▶ 出号注入（historyCount=100 期遗漏/频次/流水）
                        └─ （本方案增补，见 6.2）─────▶ 相似局势 / 分位数档案 / 聚合视图
```

**因子就是压缩器**：一条「和值区间因子在 3000 期样本上胜率 p、样本外表现 q」的结论，是把数千期压成几十 token 的可执行知识——理论视角即「压缩即理解」（Solomonoff/Hutter 归纳：预测能力=压缩能力）。

### 6.2 增补三件（从全量提取「珍贵且稀疏」信息的正规方法）

| # | 件 | 内容 | 落点 |
| --- | --- | --- | --- |
| ① | **局势指纹与相似检索** | 每期编码为局势向量（遗漏分布/和值/奇偶比/012 路/AC 值/连号等状态变量——docs/06 §4.3「条件空间」的落地）；出号时按当前指纹检索历史上最相似的 K 期注入（「类似局势出现过 12 次，后续开奖分布如实给表」）。**语义时空图（M5）的第一个实用切片，不需要图引擎，SQLite+距离函数即可** | 新增指纹表 + 检索函数；防前视硬约束：只检索「该期之前」的历史 |
| ② | **极值/分位数档案** | 每彩种离线算好（backfill 后重算）：各位置遗漏的历史分位数表、和值/跨度极值区间、最长连号等。注入时按当前局势查表：「当前蓝球遗漏 12 期 = 历史 89 分位」——罕见性有了客观度量 | 静态档案表，生成一次查询千次 |
| ③ | **聚合视图 → 提案接口**（环 A 数据面） | 给 LLM 的不是原始期次而是聚合产物：转移频次表、条件分位数、因子覆盖盲区清单。LLM 在聚合视图上提假设 → 回测引擎在全量+样本外验证 | 锚 A 的输入规格 |

### 6.3 用词澄清（主人问「稀疏」是否正确）

方向对，术语可再准：统计学里 sparse 指数据本身稀疏（大多为零/空，如 one-hot）。主人想要的实为两类东西：**高压缩比的规律摘要**（因子结论/分位数表——把海量数据压成少量可执行知识）与**罕见局势样本**（相似局势检索命中的稀缺历史切片）。「珍贵且稀疏」在锦鲤语境的最佳操作化 = **信息熵高、可压缩性好**的结论 + 稀缺样本的如实呈现。

### 6.4 对 historyCount 30→100（已拍板 B 项）的产品意见

有益但边际递减：100 期窗口统计比 30 期稳（样本 ×3.3），token 增量已核（约 1.5–2K/次，占周预算 0.7%），诚实合规。但真正的增益不在窗口加大——**窗口外全量以摘要形态进场**（6.2 三件）才是数量级差异；窗口本身到 100 期已在 LLM 可读上限附近，勿再扩。

## §8 双 Hierarchy 定位（2026-11-19 凌晨讨论增补，源自 AI 大会观点映射）

### 8.1 Model Hierarchy 的锦鲤翻译：蒸馏成 DSL，而非权重

锦鲤不训练模型（无算力/API-only/2核2G），「彩票领域专属任务模型」的落法是**以代码为载体的蒸馏**：

| 大会 Model Hierarchy | 锦鲤版 |
| --- | --- |
| 大模型（贵/慢/通用） | DeepSeek 出号会话——每期一次调用，只负责叙事合成 |
| 蒸馏出的专属小模型（便宜/快/专用） | **因子库 = DSL 代码载体的领域模型**：确定性、可验证、可版本化、零 token 执行 |
| 蒸馏过程 | 因子化流水线（卡片→DSL→回测） |
| 价值 = 成本匹配任务 | 每期选号的领域计算由因子代码零成本完成，大模型只买叙事合成那一次调用 |

- **零信号域的优势**：蒸馏成代码比蒸馏成权重更诚实——因子可解释、可防前视检验、可淘汰；权重蒸馏在零信号域只能学到格式与流程，学不到预测力。
- **锚 A 的新定位**：环 A（探索性提案）= 该蒸馏过程的**自动化**（AI 自提假设 → DSL → 回测验证）。
- **与 Q7 拍板（不分级模型）的关系**：不冲突——专属化发生在模型之下的 DSL 层，不动模型路由。若未来 token 成本承压，「蒸馏/摘要类任务换便宜模型」是 Q7 的合法重开方向（成本杠杆，非能力问题）。

### 8.3 非文本数据判定（大会观点②的校准）

- **结构化表格：完全成立**——drawstore 即表格，回测/归因全是表格计算（大会路径一「Agent 调用专业工具」锦鲤在走）。
- **时间序列：形式成立、性质退化**——零自相关（摇号机物理保证 i.i.d.）。时序方法论的可预测性部分（ARIMA/LSTM/趋势外推）必然失效；**安全子集**（描述统计/分位数/极值/指纹）不假设可预测性，全部可用——即 §6.2 三件。
- **「训原生模型」在彩票域永久关闭**（比大会「推理能力不足」更强的判定：训了也没用，信号为零）——免掉的弯路，省下的资源全投架构指标。
- **大会路径二（专业数据作为知识纳入模型体系）= 知识宫殿已在做**（卡片/因子=领域知识形式化）。

### 8.4 小模型体系的第一落点

130MB 本地嵌入模型（长期默认关）= 体系内唯一真「小模型」，用途=相似局势/记忆检索。相似检索 v1 用 SQL/距离函数（§6.2①），若检索质量实证不足，嵌入模型是 v2 升级项——符合「小模型价值 = 高频轻任务不付大模型价格」。
