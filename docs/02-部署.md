# 02 · 部署

前提：服务器已买好，能用 `ssh root@<IP>` 登录，系统是 Ubuntu 24.04。

## 第 1 步：把部署包传上去

在 **Windows PowerShell**（不是服务器里）执行，把 IP 换成你自己的：

```powershell
scp -r "D:\QQ工作区\deploy" root@1.2.3.4:/opt/dsh-deploy
```

> 如果登录用的是密钥文件：`scp -i C:\path\to\key -r ...`

## 第 2 步：一键安装

```bash
ssh root@1.2.3.4
sed -i 's/\r$//' /opt/dsh-deploy/*.sh    # 保险：去掉 Windows 换行符
bash /opt/dsh-deploy/install.sh
```

脚本会依次做：装依赖 → 设时区 → 建 `dsh` 用户 → 装 Node 24 → 装 pnpm → 装 dsh → 写 `/etc/dsh/dsh.env` → 装 systemd 服务并启动。

> **海外机器建议这样跑**（换官方 npm 源 + 顺手装 yt-dlp）：
> ```bash
> NPM_REGISTRY=https://registry.npmjs.org WITH_YTDLP=1 bash /opt/dsh-deploy/install.sh
> ```

**约 1–3 分钟**，最后会打印「服务已启动 ✔」和下一步提示。

## 第 3 步：填 API Key

```bash
nano /etc/dsh/dsh.env
```

把 `DEEPSEEK_API_KEY=` 后面填上你的 key（`sk-` 开头），`Ctrl+O` 保存、`Ctrl+X` 退出，然后：

```bash
systemctl restart dsh
```

> key 在 <https://platform.deepseek.com/api_keys> 申请，账户里要有余额。

## 第 4 步：拿到带 token 的访问地址

```bash
journalctl -u dsh -n 80 --no-pager | grep -Eo 'http://[^ ]+' | tail -1
```

会输出类似 `http://127.0.0.1:3080/?token=xxxx` 的地址。**这串 token 就是访问凭证**，别贴到群里或截图发出去。

## 第 5 步：建隧道，打开界面

在 **Windows PowerShell** 里（保持这个窗口开着）：

```powershell
ssh -N -L 3080:127.0.0.1:3080 root@1.2.3.4
```

然后在浏览器里粘贴第 4 步拿到的地址（注意是 `127.0.0.1`，不是服务器 IP）。

看到 dsh 的 Web 界面就成功了——和你现在用的桌面版是同一套东西。

## 第 6 步：验收「不下线」

```bash
systemctl is-enabled dsh      # 期望输出 enabled（开机自启）
systemctl is-active dsh       # 期望输出 active
```

测试崩溃自愈：

```bash
pkill -f 'dsh web'; sleep 6; systemctl is-active dsh    # 期望 active
```

测试重启自启：

```bash
reboot
# 等 30 秒重新 ssh 上来
systemctl is-active dsh       # 期望 active
```

三条都过了，第一阶段就算完成。

## 第 7 步：验证上网能力

```bash
curl -sI https://www.youtube.com | head -1     # 期望 HTTP/2 200 或 301
curl -sI https://www.bilibili.com  | head -1   # 期望 HTTP/2 200
yt-dlp --version                               # 装过才有输出
```

这两条通，我以后抓 B站/YouTube 的内容才不受限。

> B站 少数番剧有地区版权限制（提示「仅限中国大陆」），抓不到属正常；普通视频、搜索、UP 主页都没问题。
> YouTube 页面是 JS 渲染的，纯抓取只能拿到标题/简介这类文字；要看具体内容得读字幕：
> ```bash
> yt-dlp --skip-download --write-auto-sub --sub-lang zh,en -o '/tmp/%(id)s.%(ext)s' '视频链接'
> ```


## 日常运维命令

| 想干什么 | 命令 |
| --- | --- |
| 看是否在跑 | `systemctl status dsh` |
| 看实时日志 | `journalctl -u dsh -f` |
| 看最近 100 行 | `journalctl -u dsh -n 100 --no-pager` |
| 重启 | `systemctl restart dsh` |
| 停掉 | `systemctl stop dsh` |
| 看内存占用 | `systemctl status dsh \| grep Memory` |

## 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Unit dsh.service not found` | 没重新加载配置 | `systemctl daemon-reload` |
| 服务反复重启 | 看 `journalctl -u dsh -n 100` 的具体报错 | 多半是初始化失败或依赖缺失 |
| `EADDRINUSE` | 3080 被占 | 改 `/etc/dsh/dsh.env` 里的 `DSH_WEB_PORT`，隧道端口同步改 |
| 浏览器打不开 | 隧道没建 / 端口不一致 | 确认 `ssh -N -L` 那个窗口没关 |
| 界面能开但对话报 401/鉴权失败 | key 没填或无效 | 检查 `/etc/dsh/dsh.env`，`systemctl restart dsh` |
| 装 Node 卡住或超时 | 镜像站不可达 | 重跑并换源：`NODE_MIRROR=https://nodejs.org/dist bash install.sh` |
| 内存被打满 | 2G 偏紧 | 按 01 文档加 2G swap，或升 4G 机型 |
| `curl youtube` 超时 | 机器在境内或被限 | 确认买的是香港/日本/新加坡节点 |
| 磁盘满 | 日志或会话历史 | `journalctl --vacuum-size=200M`，清理 `/home/dsh/.dsh` 下的旧会话 |

改完配置一律 `systemctl restart dsh` 生效。

## 关于访问地址（重要）

**每次重启 dsh，地址里的 token 都会变**。别收藏，用服务器上的小工具取最新的：

```bash
dsh-url
# http://127.0.0.1:3080/?token=xxxxxxxx
```

取到之后在本地建隧道，把地址粘进浏览器：

```powershell
ssh -N -L 3080:127.0.0.1:3080 root@<服务器IP>
```

这串地址等于登录凭证，别发群里、别截图外传。

| 项 | 值 |
| --- | --- |
| 云厂商 | 阿里云（杭州） |
| 公网 IP | `120.55.184.195` |
| 系统 | Ubuntu 26.04.1 LTS / x86_64 / 2 核 1.7G 内存 / 40G 盘 |
| 交换分区 | 4G（镜像自带） |
| dsh | 0.2.1-rc.2（Node v24.21.0） |
| 服务 | `dsh.service`，enabled + Restart=always |
| 验证 | 重启服务器 30 秒后自动恢复；`dsh headless` 端到端对话正常 |

部署时踩到两个坑，已经写进 `install.sh`：

1. **npm 全局前缀**：Node 是解压部署的，npm 默认把全局包装进 Node 自己的目录，`/usr/local/bin/dsh` 根本不存在 → systemd 报 `203/EXEC`。现在脚本显式 `NPM_CONFIG_PREFIX=/usr/local`。
2. **npm 11 拦截安装脚本**：`node-pty`、`dsh-subprocess-local` 的 postinstall 被安全策略跳过 → 终端和子进程能力缺失。现在脚本带上 `NPM_CONFIG_ALLOW_SCRIPTS` 白名单。


## 卸载

```bash
bash /opt/dsh-deploy/uninstall.sh           # 停服务删单元，保留数据
bash /opt/dsh-deploy/uninstall.sh --purge   # 连用户和数据一起删
```
