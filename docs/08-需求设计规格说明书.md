## 1. 产品定位与成功指标

**定位（继承 05，不重复论证）**：彩票每期是独立随机事件，任何算法不改变概率。本产品交付的是「有人认真研究过 + 按时送达 + 诚实记账」。账本难看是功能。

**成功指标（架构指标为 KPI，Q11 建议值，⚠ 待主人确认）**：

| KPI | 定义 | 目标 | 测量来源 |
| --- | --- | --- | --- |
| 出号准时率 | 开奖日 18:00 前收到预测私聊的比例 | 100% | state.json `pushedAt` |
| 对账零漏账 | 每条正式预测最终在 ledger 有账（含补账） | 100% | predictions.json × ledger 交叉核对（v1.1 C1 修复后成立，见 FR-5.4） |
| 战果心跳 | 每个对账日 22:30 前有任一私聊（战果或致歉） | 100% | 主观 + journalctl |
| 命中率 | 只与随机基线对照观测 | 不设目标 | v2 基线机制（纪律 2） |

**用户**：单用户（主人，QQ 1017099872）。主界面 = QQ 私聊；辅助界面 = Web 面板「设置 → 彩票」；运维界面 = CLI + journalctl。

## 3. 功能需求（FR）

### FR-1 出号调度
- FR-1.1 开奖日按彩种日历（双色球周二/四/日、大乐透周一/三/六、排列三每日）在 `predictAt`（默认 17:30）触发出号，仅处理 `enabled` 的彩种。
- FR-1.2 单彩种每日最多尝试 3 次（`MAX_ATTEMPTS`），两次尝试间隔 ≥ 2 分钟。
- FR-1.3 18:10 后成功的推送标「晚到」；`catchUpEnd`（默认 19:50）后仍未出号 → phase=`skipped`，发一次致歉私聊。
- FR-1.4 3 次尝试均失败 → phase=`failed`，发一次致歉私聊。
- FR-1.5 出号与加餐全局串行（`inFlight` 互斥），不并发唤醒会话。
- 验收：UC-1 主流程 + 三分支；对应测试「开奖日历」4 例。

### FR-2 官方数据获取
- FR-2.1 三源：福彩 `findDrawNotice`（双色球，含各奖级单注奖金）；体彩 `getHistoryPageListV1.qry` gameNo=85（大乐透）/ 350133（排列五，取前三位为排列三）。
- FR-2.2 体彩请求必须带浏览器头（Referer/Origin/UA），超时 15 秒；福彩 GBK 响应按 utf8 解析（所需字段全 ASCII）。
- FR-2.3 期号推算：`nextIssue` 支持福彩四位年/体彩两位年与跨年（2026121→2026122；26120→26121；2026153→2027001）。
- 验收：`koi.mjs history` 三彩种实测；跨年测试 2 例。

### FR-3 AI 产出契约（三道保险）
- FR-3.1 唤醒提示词内嵌数据包（遗漏/频次/近 10 期流水），要求她把结果写进**约定路径的 JSON 文件**（文件契约，绝不解析自由文本）。
- FR-3.2 `validatePicks` 硬校验：个数、去重、范围、整数；不合法 → 打回重写一次（60 秒内等文件）→ 仍不合法 → `randomPicks` 随机兜底。
- FR-3.3 兜底号在推送与面板中标注「兜底号」（纪律 4 兜底透明）。
- FR-3.4 结果文件等待上限 4 分钟；用后即删。
- 验收：校验测试 3 例（合法/坏号/三彩种）；兜底 200 轮合规测试。

### FR-4 推送
- FR-4.1 NapCat HTTP `/send_private_msg` 私聊 `push.target`；基址必须回环（`assertLoopback`，配置公网地址直接拒绝）。
- FR-4.2 出号成功后推送失败 → 每 60 秒重试直至成功；失败原因 `pushErr` 持久化并在面板显示。
- FR-4.3 加餐推送失败不重试，号在面板展示（job.status=`push-failed`）。
- FR-4.4 ⚠（评审遗留，P2）：致歉消息依赖同一通道，通道全挂时致歉落日志不上屏——接受，运行手册以「22:30 无消息=出事」兜底（见 NFR-4）。

### FR-5 对账
- FR-5.1 22:00（`settleAt`）起，对当日已出号彩种与跨天顺延条目对账；**按期号精确匹配**（`latest.issue === entry.issue`），不是这一期 = 未公布。
- FR-5.2 未公布每 15 分钟重试，最多 8 轮；跨天条目（carry）不限轮次持续重试直至公布。
- FR-5.3 判奖：`enumerateBets` 拆注（双色球 C(8,6)=28 注、大乐透 C(7,5)×C(2,2)=21 注、排列三 1 注）→ `judge` 逐注按官方奖级判；浮动奖（一/二等）当晚按 0 计并标「含浮动奖」。
- FR-5.4 **⚠ BUG-K1（v1.1 必修，N1 关联）**：现行代码在 `settleGiveUp`（23:30）后把条目标 `settled` 且**不记账**——成本不进 ledger、`settle --date` 无法 reopen、次日 carry 跳过（`e.settled=true`）。官方公布晚于 23:30 的每一期都会**静默漏账**，春节休市期会连续漏。修复规格：放弃时仍记 `cost`（`prize:null` + `settleNote`），公布后自动/手工补判奖；`settle` 增加 `--force` 重开已放弃条目。
- FR-5.5 **⚠ 休市日历（v1.1，N1）**：配置新增 `holidays: ["YYYY-MM-DD"]`，命中日期不出号不对账；官方每年休市公告后人工维护一次。

### FR-6 模拟账本
- FR-6.1 口径 =「若每期正式预测都买」：daily 条目入账 `cost` 与判奖 `prize`；加餐（quickpick）不记账。
- FR-6.2 汇总口径：投入/中奖/净额/期数/最好一期；推送与面板共用同一文案函数。
- FR-6.3 一/二等奖浮动金额官方次日才公布；v1 当晚按 0 计。⚠（P2-1）次日自动回填修正为可选项，默认不做。

### FR-7 面板（Web）
- FR-7.1 四条 API：`GET /dsh-koi/api/status`（状态+日历+账本摘要+推送通道探测）、`POST|GET /dsh-koi/api/quickpick`（加餐+轮询）、`POST /dsh-koi/api/test-push`。
- FR-7.2 所有路由 fail-closed：仅回环 + `connection.requestRejection` 信任栅栏。
- FR-7.3 面板 UI 仅一节：今日日历、每彩种卡片（phase/号/兜底标注/加餐按钮）、测试推送、账本摘要；**不做**设置页/历史页。
- FR-7.4 加餐任务在内存队列（上限 20），重启即失——已知且接受。

### FR-8 CLI（tools/koi.mjs）
- FR-8.1 七命令：`history / validate / settle [--date] [--push] / ledger [--reset] / push / deps [--json] / demo-predict`。
- FR-8.2 `deps` 体检：配置存在、目标 QQ 格式、NapCat 在线、数据目录可写、三数据源连通（各抓 1 期）、今日开奖彩种。
- FR-8.3 ⚠ BUG-K2（v1.1 C3）：CLI 写盘是裸 `writeFileSync`，与调度器的原子写（temp+rename）不一致，22:00–23:30 手工补账与调度器并发时可能整文件互相覆盖。修复：CLI 统一原子写 + runbook 注明避开窗口。

### FR-9 配置
- FR-9.1 `koi.config.json` 字段：`push{target,napcatHttp}`、`time{predictAt,catchUpEnd,settleAt,settleGiveUp}`、`games.{ssq,dlt,p3}.enabled`、`historyCount`、`historyTail`、`persona`（空=内置元气小财迷）。
- FR-9.2 每 tick 现读配置 → 改动 30 秒内生效；JSON 损坏回退默认值；首跑自动落默认配置。
- FR-9.3 v1.1 预留：`holidays` 数组（FR-5.5）。

### FR-10 状态持久化与恢复
- FR-10.1 三文件落盘：`state.json`（当日状态机+carry）、`predictions.json`（预测流水，settle 时原条目上补结果字段）、`ledger.json`（账本）；写盘 temp+rename 原子化（调度器侧）。
- FR-10.2 重启后：当日 phase 续跑（predicted 未推送→继续推）、未对账条目进 carry（仅扫 `prevDate` 一天；⚠ C8：应扫所有未 settled，防多日宕机漏顺延）。
- FR-10.3 v1.1 预留：predictions/ledger 顶层加 `schemaVersion: 1`（演进规则见 docs/10 §6）。

## 6. 边界与非目标（v1 明确不做）

继承 05 四条（加餐不记账 / 浮动奖当晚 0 计 / 桌面不适配 / 排列三只直选），并补充：

- **不接真实支付/出票**：模拟账本口径，不与任何购票渠道对接；
- **休市期间行为**：未修 FR-5.5 前，休市日照常出号且当晚对账必然放弃（触发 BUG-K1 漏账）→ v1.1 修复前，运行手册注明「春节等休市公告发布后手工 `games.*.enabled=false`」作为临时措施；
- **不做多用户**：`push.target` 单号；面板无鉴权（回环+SSH 隧道模型下接受）。
