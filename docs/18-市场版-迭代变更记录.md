# 18 · 锦鲤市场版 · 迭代变更记录

## 1. 记录定位与约定

### 1.1 记录定位

本记录承载市场版实机体验阶段（2026-10-25 起）的缺陷修复与小需求变更，是该阶段**迭代事实的权威记录**：本阶段的全部代码改动、行为变化与验证结论，均以本记录为准。

### 1.2 阶段定位与冻结范围

主人已拍板（2026-10-25）：本阶段定位为「缺陷修复 + 需求小改动」的直接迭代，**不走四阶段需求管线**（RR → IR → SDD → 确认书），不产生 docs/15/16/17 的结构化需求变更。据此，需求分析规格（docs/15，IR）、软件设计文档（docs/16，SDD）与实施方案确认书（docs/17）在本阶段全部冻结，不随迭代即时修订；本记录即本阶段的唯一落盘载体。

冻结不等于口径悬空：凡本阶段变更与冻结文档既有口径存在差异的（如 TF-1 之于 docs/15 的 DC-106），在对应条目的「影响范围」中显式登记回流事项，统一合并至 docs/15 的 v1.0.2 升版处理（安排见第 3 节），不在本阶段逐条改动冻结文档。

### 1.3 升格条件与流程

任何登记于本记录的改动，若在实施或验证过程中实质演变为新能力，或影响面超出「缺陷修复 / 需求小改动」的预期边界，即不再以变更条目形式继续扩展，**升格走正式需求流程（RR → IR → SDD → 确认书）**，并在本记录对应条目标注「已升格」及升格去向，使本记录与正式管线之间保持可追溯。变更请求一律显式处置——接受、延后或升格，不默默吸收。

### 1.4 条目规范（四要素）

每条变更按「问题背景 / 变更决策 / 影响范围 / 验证结果」四要素完整记录：问题背景交代实机体验发现的现象、根因与产品预期落差；变更决策记录主人拍板结论；影响范围列明代码落点及必要的文档口径联动与测试断言更新；验证结果给出全量测试基线结果或实机确认结论。四要素齐备、自洽，每条变更可独立审阅。

### 1.5 质量门槛

全部变更须通过全量测试基线（当前 143 项，随新增递增）方可交付主人验证；随变更同步更新的测试断言属于变更内容的一部分。

### 1.6 编号与留痕

变更条目编号采用 TF（Tuning & Feedback）前缀，顺序递增、不回收。原始工作草稿（主人实机反馈与修复摘要）留存于 docs/decisions/市场版-D-默认决策记录.md「体验反馈修正」节；本记录为其润色定稿，并以本记录为本阶段的权威事实口径。

## 2. 变更条目（2026-10-25 · 第一批）

本批共 5 条（TF-1～TF-5），均源于主人 2026-10-25 实机体验反馈；各条验证状态详见对应「验证结果」与第 3 节。

### TF-1 投注结构档位表补充 2 元基础档，并统一出厂默认

- **问题背景**：实机体验发现，各彩种投注结构档位表的最小档均为复式结构（双色球最小为红7+蓝1、大乐透最小为前6+后2），缺少面向轻度用户的 2 元单式基础档；且出厂默认档指向复式最小档，与「默认推荐轻量参与」的产品预期不符。
- **变更决策**：主人拍板——所有彩种提供 2 元单式基础档，其余档位全部保留，出厂默认统一推荐 2 元档。
- **变更内容**：投注结构档位表新增 `ssq-d6b1`（单式 6+1，1 注 / 2 元）与 `dlt-f5b2`（单式 5+2，1 注 / 2 元），置于各彩种档位序列首位；`defaultTierFor` 三彩种出厂默认统一指向 2 元档（排列三 `p3-x1` 原生即 2 元档，不变）；主人本地实例配置同步切换至 2 元档。
- **影响范围**：`lib/tiers.js`（档位表与出厂默认）；docs/15 的 DC-106 初始档集口径以本条为准（回流至 v1.0.2 升版，见第 3 节）；测试断言同步更新（market-tiers / market-config / market-index 三处）。
- **验证结果**：全量测试 143/143 通过；2 元档由既有判奖通用性路径（FZ-1 零修改）与基线同构机制直接覆盖，无冻结区改动。

### TF-2 桌宠小组件关闭闭环（缺陷修复：关闭动作不生效）

- **问题背景**：实机体验发现，桌宠小组件（下文简称「桌宠」）的关闭按钮（×）点击后无任何可见效果；且因启动逻辑从不读取该开关状态，重启应用后桌宠依然存在——关闭动作在整条链路上均不生效。
- **变更决策**：建立「启动检查—立即卸载—持久化—面板重开」的完整关闭闭环。
- **变更内容**：①桌宠挂载前读取 `pet.enabled` 配置，为 `false` 时不挂载；②关闭按钮点击即持久化配置并**立即卸载**桌宠组件（原实现仅写配置、不卸载）；③设置 → 彩票面板新增「桌宠」开关，重新勾选即时恢复挂载。
- **影响范围**：`lib/client.js`（挂载逻辑、桌宠组件、配置面板）、`lib/index.js`（状态接口新增 `pet` 字段）。
- **验证结果**：全量测试 143/143 通过；关闭后通知事件链路不受影响（事件仍经面板渠道与其他已启用渠道分发，与既有设计一致）。

### TF-3 桌宠浮层配色自持（缺陷修复：通知内容不可读）

- **问题背景**：实机体验发现，桌宠通知气泡呈「深底深字」的不可读状态。根因为浮层样式引用宿主主题变量（`--dsw-alias-*`），但浮层挂载于文档根部、位于变量作用域之外，文字色全部回落为继承值。
- **变更决策**：桌宠浮层采用自持配色，不依赖宿主 CSS 变量。
- **变更内容**：气泡、消息列表、关闭按钮改为显式深色卡片配色（背景 rgba(24,26,34,.97)、文字 #e8eaf0、描边 rgba(255,255,255,.14)），任何宿主主题下保证可读。
- **影响范围**：`lib/client.js`（桌宠样式段）。
- **验证结果**：主人实机确认可读性达成（本条源于主人截图反馈，修复后经实机确认）。

### TF-4 测试通知独立事件类别（变更：测试事件不得伪装为告警）

- **问题背景**：实机体验发现，点击「测试通知」后桌宠出现「⚠️ 锦鲤告警」样式的消息，与真实故障告警混淆。根因：测试事件在通知事件层错误复用 `alert`（告警）类别。
- **变更决策**：测试事件使用独立的 `test` 事件类别，与告警明确区隔；告警的警示语义不被稀释。
- **变更内容**：通知事件层的事件类别白名单（EVENT_KINDS）扩充 `test`；测试事件类别改为 `test`；桌宠气泡与事件列表的类别标题映射新增「测试通知」。
- **影响范围**：`lib/events.js`（类别白名单、测试事件）、`lib/client.js`（标题映射）、测试断言同步更新（market-index）。
- **验证结果**：全量测试 143/143 通过；真实故障告警的呈现与语义不变。

### TF-5 桌宠未读标记闭环（缺陷修复：已读状态不生效）

- **问题背景**：实机体验发现，存在未读事件时点开查看、收起后未读角标仍不清除。根因有二：①「标记已读」在游标为空时将字符串 `"null"` 写入本地存储，此后无法匹配任何事件标识，未读数恒等于全部条数；②收起动作未触发兜底标记。
- **变更决策**：对标记已读链路实施空值防御并建立统一兜底，使打开与收起两条交互路径的已读状态均正确生效。
- **变更内容**：①本地存储读写增加空值防御（不写入空游标、读取时过滤历史脏值）；②统一标记已读逻辑（游标为空时兜底取最新事件标识）；③打开与收起动作均执行标记。
- **影响范围**：`lib/client.js`（桌宠未读逻辑）。
- **验证结果**：全量测试 143/143 通过。

### TF-8 自动模式关闭选项（需求小改动 + 责任边界定稿）

- **问题背景**：实机体验发现，自动模式只能通过向导开启，开启后没有任何面板内的关闭选项（改配置文件/CLI 对市场用户门槛过高）；由此引出产品责任边界问题——关闭/卸载之后，用户的智能体是否仍在运行、插件是否需要为其负责。
- **变更决策**：①配置面板每彩种新增**模式下拉**（自动/手动/关闭），切换即时生效（下一轮 tick，约 30 秒）；降档（自动→手动/关闭）免门控，开启自动仍走四项门控向导。②关闭语义定稿为两段式：**停止未来**（该彩种出号与推送下一轮 tick 起停止）+ **不逃存量**（当期已出的正式预测与未结清账目仍完成对账入账——调度器对账段的产品注释即「账本诚实优先于模式门，已出的号必对账」，BC-006）。
- **责任边界（产品定论）**：插件全部运行物均在用户自己的 harness 进程内（调度器定时器、被唤醒会话、事件层、本地数据），作者侧不存在任何远端组件——「对用户远端智能体负责」在架构上不成立。插件承诺三条边界：①进程内生命周期干净（卸载/停用触发清理钩子，调度器停止、定时器销毁、桌宠卸载，无残留进程）；②用户数据保留（卸载不删 ~/.dsh/koi 的档案/账本/事件，重装无缝续跑）；③账目善后（关闭/卸载前已产生的预测完成对账，未结清条目由 carry 扫描接管）。超出三条的「持续负责」属于作者侧常驻服务架构，锦鲤明确不采用。
- **影响范围**：`lib/client.js`（配置面板⑥区模式下拉与切换逻辑）；调度器/模式路由语义无改动（setMode 降档免门控为既有实现）。
- **验证结果**：全量测试 144/144 通过。

### TF-9 面板信息架构重构：主页所见即所得 + 双子页（需求小改动）

- **问题背景**：主人实机体验拍板——进入页面第一眼应看到核心功能（所见即所得）；彼时主页面纵向堆叠了彩种卡片、数据回拉、学习上传、因子结论、配置面板全部内容，核心操作（现在来一注）被淹没。
- **变更决策**：信息架构改为「主页 + 双子页」页签制。**主页「概览」**= 精简状态行 + 三张彩种卡片（现在来一注 / 自动模式向导，所见即所得）；**子页「事件」**= 事件列表、全部标为已读、心跳告警说明（页签带未读中奖数角标，点开即标记已读）；**子页「学习与设置」**= 数据回拉区 + 学习上传区 + 因子结论区 + 配置面板六大区 + 成本估算 + 页脚。「测试通知」按钮从概览卡片迁至设置①渠道区（与「测试渠道配置」并列，分别验证事件层链路与适配器配置）。
- **影响范围**：`lib/client.js`（KoiSection 渲染重构 + 新增页签样式）；无后端改动、无接口形状变化。

### TF-11 分块拆卡（缺陷修复：大文档拆卡两次交卷不合格被整体拒收）

- **问题背景**：主人上传 420.6KB 的《彩票投资指南》（清洗后逼近 20 万字符单次上限），拆卡两次交卷均「cards 数组缺失」被整体拒收。根因：拆卡为**单次全文交卷**设计，近 20 万字符的阅读+提取负载超出模型单次合规输出能力——正是第二波设计阶段预警「分块拆卡列待办」的边界被真实文件踩中。
- **变更决策**：实现分块拆卡——清洗文本按 3 万字符（可配 `ingest.chunkChars`）分段；每块独立「读文件→交卷→校验」，不合格打回一次；**内容不合格=确定态**（单块失败不拖垮整体，部分成功口径，失败块记入任务留痕）；**交卷超时=瞬时态**（落 pending-llm 由宿主续跑重拆，S-119 语义保持）；块间同名去重（跨块边界重复提及同一技巧不重复入库）。
- **影响范围**：`lib/ingest.js`（splitIntoChunks 导出、分块循环、buildSplitPrompt 分块注记、超时/内容不合格双轨语义）；测试桩正则放宽匹配分块交卷命名；超时恢复用例回归通过。
- **验证结果**：全量测试 209/209 通过。主人重新上传原文件即可走分块流程（约 14 块）。

### TF-14 backbone 测试时间炸弹（缺陷：硬编码日期夹具 7 天后必炸）

- **问题背景**：主人跨平台回归时发现 236 项测试 1 项失败（market-index backbone 用例，其他平台收批时报全绿）。根因：夹具开奖日期硬编码 2026-10-22/21/23，`ensureRecent` 零网络判定要求最新期距今 ≤7 天（`isStaleDraw` 对比真实今天）——**10-29 起夹具自然过期**，测试转走真实网络路径（12.8s 等网络）→ `fetched:0` 断言失败。与 B2/B3 重构无关，纯测试设计缺陷（时间炸弹）。
- **变更内容**：夹具日期改为相对当天生成（`Date.now() - offset`），测试永久自洽；附注释记录炸弹成因防复发。
- **影响范围**：`tests/market-index.test.mjs` 夹具段（仅测试）。
- **验证结果**：全量测试 236/236。教训入档：**任何「新鲜度」相关测试夹具禁止硬编码日期**。
