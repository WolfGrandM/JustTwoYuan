# 14 · 锦鲤市场版 · 需求材料（RR + 拍板记录 + 待办池）

> **来源**：2026-10-24 与主人的逐条需求讨论（协作模式：主人给想法与拍板，AI 细化）。
> **现网保护约定**：服务器生产实例（v1.1，2026-10-24 上线，commit 4627d04/545f491）运行中，今晚有真实出号/对账；**本管线全程只改本地工作区，禁止 ssh/scp/远程操作/任何部署**；线上版本不受本地改动影响。

## 一、背景与产品定位

插件将进入 DSH 插件市场——从「个人工具」变为「**自包含产品**」：用户从市场下载，装进自己的 harness（Windows 桌面 app 或用户自己的服务器，双 profile 完整支持），调度、数据、学习、桌宠 UI 全部在用户本地运行，**与作者的服务器无关**。作者自己的服务器实例（QQ 私聊通知）只是作者本人的一种部署选择。

两条产品根原则（贯穿全部需求）：

1. **零内嵌凭证**：插件永不内嵌作者的任何 key/账号/收款渠道；LLM 流量用用户自己 DSH 的模型配置（用户装 DSH 时已填自己的 key）；通知渠道凭证由用户自行提供。
2. **诚实条款不动摇**：docs/12 的 BC-001~016 全部继承；任何新功能不得把「命中率」变成优化目标；「学习/推荐/大力蹬」的文案一律不得宣称改变中奖概率。

## 二、需求清单（12 项成立 + 1 项撤销）

### R1 市场就绪 · 通知渠道解耦
把「通知」从 QQ 私聊实现中剥离：插件内部产出**通知事件**（预测/战果/致歉/告警 + 时效 + 正文），由可插拔渠道层决定送达。现有 FR-005 统一重试/补发语义下沉到事件层；心跳语义泛化为「全部启用渠道均静默 = 异常」。与 R13（QQ 剥离）合并落地。

### R2 技巧文件上传入口 + 学习闭环（知识宫殿入库半环）
用户上传选号技巧文件（PDF/EPUB/TXT/MD，含强转 MD——P3 拍板：preprocessor 清洗剥图/OCR 噪声/断行）→ 结构化技巧卡片（语义去重）→ 可计算卡片入库。**回测引擎不在本轮**（依赖 M1 数据地基，第二波）。产品文案明示「学习 = 严格回测检验，结论可能证明技巧无效」。

### R3 多 Agent 角色可配置（已锁定）
数据官/策略师×N/质询者/主持人框架固定；**数量 + 每角色任务提示词**可配、策略师可克隆；纪律围栏 FZ-7（用户可改「角色怎么想」，不可改「纪律怎么算」：硬校验/基线/归因/推送契约/兜底全部结构锁定）；配置版本化 stamp 进档案（FR-021）；配置页实时显示每期成本估算。数量配置较轻随本轮管线，任务提示词编辑随 M3 编排器。

### R4 投注结构档位制 + 今日最佳策略推荐
- **选 X 注**：预设合法投注结构档（标明每期价格，如排列三单式×1/×3/×5、双色球红7+蓝1/红8+蓝1/红9+蓝2、大乐透前6+后2/前7+后2/前8+后3 等），用户选档；判奖引擎（FZ-1，本就支持任意合法复式）与基线同构（DC-002）现成支持；换档下期生效，账本按实际结构记。
- **今日最佳策略推荐**：Advisory——默认开启、推送/面板展示、标「建议不记账」、**永不自动改变正式预测结构**；「最好」= 预注册的结构性判据（活跃因子战绩引用 + 号码集大小/成本权衡 + 推荐战绩观测），理由全文入档案；周报做「采纳建议 vs 默认档」对照（纯观测）。红线：「最好」绝不意味着提高中奖概率。

### R5 作者捐献入口
面板「彩票」卡片底部一行小字 + 折叠收款码；纯自愿、与功能零挂钩、不进推送、零外联、静态不做定时提醒。**素材（收款码/链接）与文案（A/B/C）待定 → 待办池**。

### R6 每角色 token 分配配置
三层配置：周度总预算（硬顶，超限走既有降档链）→ 活动类别分项（出号/博弈/复盘/学习，70%/90% 预警线不变）→ 博弈类内每角色权重（实时换算额度 + 每期成本估算）；高级项 = 每角色绝对值覆盖（注入上限默认 4000、单角色调用上限）。入口 = 面板为主 + 配置文件/CLI 等价。作者实例继续 1000 万/周，产品默认 150 万/周。

### R7 思考强度力度旋钮
统一四档：**跟随宿主默认（出厂）/ 省 / 标准 / 大力**——自动映射到当前模型实际可用的杠杆：模型支持思考强度参数则直传；不支持（如 DeepSeek chat）则映射到推理轮数/互评深度（同一模型不换型，Q7 不分级拍板保持）；力度档 stamp 进每期档案。配置页明示「力度影响分析质量与 token 成本，不影响中奖概率」。

### R8+R11 每彩种自动/手动模式 + 自动门控 + 数据架构
- 每彩种三态：关（现状）/ **手动**（点「现在来一注」→ 抓近期开奖记录参考学习 → 推荐；**不对账不记账**）/ **自动**（完整流水线：出号+对账+记账+全渠道通知）。市场新用户**默认手动**。
- 「现在来一注」= 永久基础层（加餐语义，永不记账），自动模式下依然可用。
- 自动模式 = 可选加挂层，开启走引导向导，**必选项门控**：通知渠道≥1 可用 + 投注档位已选 + 出号时间已设 + 诚实条款确认勾选；首次开启从数据底座拉历史（分钟级）。
- 每彩种独立出号时间（默认 17:30，校验早于该彩种开奖）；harness 弹窗在分析完成时触发。
- **数据架构（改判）**：官方自拉为底座（每用户一次性约 430 请求、15–30 分钟，分批错峰）+ 增量挂 22:00 对账（零独立抓取）+ CDN 仓库降级为**默认关闭**的可选加速（用户知情选择）+ 校验层公共化。**数据源白名单铁律：仅福彩官网与体彩 webapi 两个官方一手源，永不接第三方彩票站**；结构校验闸（期号格式 DC-006/日期合理性/号码值域/连续性）不过关即拒用；抓过即入本地库，学习永不重复依赖网络。

### R10 输出详略两档
**简洁**（只号码 + 强制合规字段）/ **叨逼叨**（号码 + ≤100 字思考过程摘要——主持人输出 schema 的结构化 summary 字段，非事后删减）。现行「完整分析全文推送」取消：全文在面板（点开看）+ 档案（永久）。强制合规字段任何模式保留：兜底/加餐/补发/基线缺失标注 + 诚实基调句。全局一档，不做按渠道分档。

### R13 QQ 剥离
市场发布的包**物理不含** qq.js 适配器与 QQ 配置字段（push.target/napcatHttp 等）；作者实例 = 市场包 + 私有 qq.js 适配器补丁（不发布）。核心对「注册但缺适配器文件的渠道」报清晰配置错误。剥离范围：推送通道、配置字段、deps 探针、面板文案、心跳措辞；QQ 私聊聊天属于宿主 onebot 不在 koi（市场版无此依赖）。市场默认渠道集 = 面板弹窗（内置）+ 社区适配器扩展接口（核心机制，即作者 qq.js 的挂载方式）；通用 webhook → 待办池第二波。

### R14 桌宠小组件（基础通知版）+ 桌面适配（已锁定）
- **桌面适配**：废除 v1 NFR-009「桌面 Electron 不适配」——插件双 profile（桌面/服务器）完整运行：调度器进用户 harness 的 Node 进程、数据落用户本地 ~/.dsh/koi、通知走渠道层、模型用用户 DSH 配置。
- **桌宠 = harness 右下角小组件**（in-harness，非系统级）：基础通知版 = 小鱼图标常驻（可整体关闭）+ 新通知事件冒泡消息卡 + 小红点 + 点击展开近期消息列表；浏览器/桌面系统通知为可选增强（授权后）。与服务器无关；消息源 = 通知事件层（R1）。
- **运行前提如实告知**：桌面 harness 非 7×24——自动模式需要开奖时段 harness 处于运行状态（补跑窗口 19:50 兜底一部分；关机/睡眠则错过），写进自动模式开启引导；想要全天候可自建服务器部署。

### ~~R9 人设预设~~（已撤销）
主人决定保持插件简洁，预设包不做；现有 `persona` 自由文本字段原样保留（v1 已有，零新增）。
