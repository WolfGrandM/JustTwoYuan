## 2. 管线提案（压缩两阶段，复用第二波形态）

| 阶段 | 内容 | 产物 |

| **A 设计定稿** | 以 docs/11/12 为输入实读现状代码（cards/ingest/scheduler/archive 面）→ M4 实施细化（模块边界/时刻表接入/口径裁决 a、b 落纸）+ FTS5 落点 + ADR-0007 + docs/15 回流草稿 | docs/27 附节或独立设计文档 + 决策记录 |

**纪律**（全程）：纯本地——零 ssh、零部署、零 npm 安装、零服务器接触；不碰冻结区（FZ-1 判奖 / FZ-4 围栏 / FZ-5 settle-core / FZ-6 status 语义）；精确路径 add、禁 push；BC-001 诚实条款与 BC-008「周报只观察不裁决」原样进代码不变量；17:00–22:00 部署禁窗不涉（无部署）。

**模型与成本**：全 GLM-5.3-Flash（历史 A 批全 flash 实测 1,275 万量级；两阶段合计估 2,000–3,500 万）。**我不掌握 Start Plan 额度池读数**——点火前主人可自行看一眼账面；管线每任务落盘可中断续跑。

**与今日验收无冲突**：17:40 / 22:10 两个验收 automation 独立运行，与管线并行互不干扰。

**触发方式**：主人一句话——「ok 全做」/「F1 做、F3 只要 ADR」/「先跑 A 阶段我审完再 B」皆可；CreateWorkflow 若 Start Plan 不可用，降级为主会话顺序跑（A→复核→B→验收门），产物与纪律不变。
