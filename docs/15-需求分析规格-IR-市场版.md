## §1 基本信息

### 1.1 项目背景

需求价值：dsh-koi 已完成 v1.1 上线（执行层闭环 + 修复包），但它是按「作者个人工具」设计的——QQ 私聊硬编码、服务器专用、配置里留着作者残留值。本需求集把插件改造为**市场就绪的自包含产品**：用户从插件市场下载后，装进自己的 harness（Windows 桌面 app 或自己的服务器）即可完整运行调度、数据、学习与桌宠 UI，与作者的服务器无关；通知渠道可插拔且凭证归用户；投注结构、角色阵容、token 预算、思考力度、输出详略全部可个性化配置。同时把学习闭环的「入库半环」（上传→摄入→卡片库）落地，为 M1 数据地基就绪后的回测引擎铺路。

需求描述：本需求集 = ①通知事件层与渠道适配器（桌宠内置渠道 + 扩展接口 + QQ 私有化剥离）②桌宠小组件（基础通知版）与桌面 profile 适配 ③配置面板个性化（渠道凭证/角色数量/预算权重/力度/详略/投注档位）④投注结构档位制与策略推荐 advisory ⑤学习入库半环（上传/摄入/卡片库/期望管理文案）⑥数据自给架构（官方自拉底座 + 增量挂对账 + 校验公共化）。它**不是**重写执行层——v1 冻结区 FZ-1~6 与全部既有测试保持；也**不是**预测能力承诺——诚实条款贯穿，新增文案零概率宣称。

**RR 来源**：docs/14（2026-10-24 与主人逐条讨论的完整材料：12 项需求 + 19 项拍板 + 锁定项 + 待办池）。全部拍板已落定，本 IR 不再设「待主人评审确认」事项；阶段A 如发现新歧义按无人值守默认纪律定值并登记 docs/decisions/市场版-A-默认决策记录.md。

### 1.2 结构化信息

|维度|内容|
|-|-|
|Who|市场用户（在自家 harness 上运行插件的 DSH 用户，桌面 app 或自有服务器）；作者（自有服务器实例 + 私有 qq 适配器 + 市场维护者）；系统角色：dsh-koi（自包含产品）、可选私有适配器（qq.js，仅作者实例）|
|When|随 harness 运行而 tick（桌面 profile 非 7×24，自动模式要求开奖时段 harness 在运行，补跑窗口至 19:50）；每晚 22:00 对账（自动模式）；事件触发的通知/上传/配置变更|
|What|可插拔通知（事件层统一重试/补发/心跳）、桌宠小组件、个性化配置面板、投注档位与策略建议、学习入库半环、数据自给与校验|
|Why|插件市场化：用户不愿交出 QQ/作者流量不可被共用/数据再分发有法律风险；同时产品化本身倒逼配置、文案、部署形态全面升级|
|Where|用户本地 harness（Windows 桌面 app 为主力形态，双 profile 支持）；无服务器依赖、无作者服务依赖|
|How Much|市场默认 token 周预算 150 万（用户自由调整，硬顶+降档链不变）；通知渠道 0 成本起步（桌宠内置）；数据自拉一次性约 430 请求|
|How|用户在面板配置一切（渠道凭证/角色/预算/力度/详略/档位），QQ 不再是必选项；「现在来一注」永远是零门槛基础层|

## §2 核心能力

### 2.1 场景分析（种子集，阶段A 补全异常/备选路径）

|编号|路径|类别|触发|步骤|
|-|-|-|-|-|
|S-101|主成功|业务|市场用户安装插件|桌宠图标出现在 harness 右下角 → 引导卡片提示配置 → 「现在来一注」立即可用（零配置门槛）|
|S-102|主成功|业务|用户开启自动模式|引导向导：通知渠道 → 投注档位 → 出号时间 → 诚实条款确认 → 拉取历史库（进度条，分钟级）→ 校验 → 下一期正式运转|
|S-103|主成功|业务|自动模式出号完成|通知事件产生 → 桌宠冒泡（+已启用渠道分发）→ 用户点开看号码（简短）；全文在面板/档案|
|S-104|主成功|业务|22:00 对账|官方实时抓开奖 → 判奖记账 → 战果通知事件 → 桌宠冒泡 → 增量入库（与对账共用抓取）|
|S-105|主成功|业务|手动模式点「现在来一注」|抓近期开奖记录（读本地库优先）→ AI 参考学习 → 推荐号码（标注「手动推荐 · 不记账」）|
|S-106|主成功|操作|用户调整角色阵容/预算/力度/详略/档位|配置面板编辑 → 实时成本估算 → 版本 stamp → 下一轮 tick 生效|
|S-107|主成功|业务|用户上传技巧文件|面板选择/拖入 → preprocessor 清洗 → 拆卡（语义去重）→ 卡片入库 → 状态可见；文案明示「结论可能证明技巧无效」|
|S-108|扩展|业务|用户选「今日策略建议」查看|主持人输出结构偏好与理由（advisory，标「建议不记账」）→ 用户手动换档或不采纳|
|S-109|扩展|业务|作者实例运行|市场包 + 私有 qq.js 适配器 → QQ 私聊通知照旧；其余行为与市场版一致|
|S-110|异常|业务|全部启用渠道静默（自动模式对账日 22:30 后）|心跳告警事件 → 桌宠冒泡 + 渠道重试；泛化自 v1「无私聊=异常」|
|S-111|异常|业务|官方数据源被拦/结构校验不过|探针报✗ + 拒用本期数据（绝不静默学习假数据）→ 重试/提示用户可选社区镜像（默认关闭项）|
|S-112|异常|业务|注册的渠道类型缺适配器文件|核心报清晰配置错误（不崩溃）：「渠道 X 的适配器缺失，请在渠道目录补入或停用」|
|S-113|异常|业务|配置值非法（预算为 0/档位越界/时间晚于开奖）|面板即时校验拒绝 + 说明；CLI/配置文件路径同样校验|
|S-114|异常|维护|桌面 harness 在开奖时段未运行|出号错过 → 补跑窗口（至 19:50）内开机则补跑；过线则按既有放弃+致歉语义（通知进桌宠）|
|S-115|备选|维护|用户从市场包升级|私有 qq.js 适配器与用户配置不受影响（目录隔离）；版本握手沿用 BC-010 精神|

### 2.2 业务规则（增量，继承 docs/12 BC-001~016 全部）

|编号|描述|原因|
|-|-|-|
|BC-101|零内嵌凭证：插件代码与配置模板不含作者任何 key/账号/收款渠道；LLM 调用一律走用户 DSH 模型配置|市场化的信任根基；作者流量隔离|
|BC-102|通知事件层唯一：所有出站通知（预测/战果/致歉/告警/建议）先成为结构化事件，重试/补发/心跳语义在事件层实现一次，渠道适配器只做传输|FR-005 语义跨渠道复用；渠道增删不改业务|
|BC-103|市场包零 QQ：市场发布的包不含 qq 适配器文件与 QQ 配置字段；QQ 仅以私有适配器形态存在于作者实例|主人拍板（R13）；「不交出 QQ」的用户信任|
|BC-104|数据源白名单铁律：官方数据仅来自福彩官网与体彩 webapi 两个一手源，永不接第三方彩票站；结构校验（期号格式/日期/值域/连续性）不过即拒用|假数据防御；法律风险最小化（作者不分发数据）|
|BC-105|数据自给：默认架构 = 用户官方自拉底座 + 增量挂对账；任何「作者侧数据分发」只能是默认关闭、用户知情选择的加速项|法律风险归属清晰；延续 R8 拍板|
|BC-106|角色围栏（FZ-7）：用户可配置角色数量与任务提示词，但硬校验、随机基线、归因代码化、推送契约、兜底标注在角色之外结构锁定，任何自定义提示词不可触及|防止用户配置侵蚀产品纪律|
|BC-107|成本透明：任何影响 token 消耗的配置（角色/预算/力度/详略）必须在配置页实时显示估算成本；力度与档位 stamp 进预测档案|用户自己的 key 自己做主；归因可分段|
|BC-108|输出合规字段恒在：简洁/叨逼叨两档均保留兜底/加餐/补发/基线缺失标注与诚实基调句；叨逼叨摘要 ≤100 字（结构化 summary 字段）|详略是风格不是豁免|
|BC-109|策略建议不越权：「今日最佳策略」只能是 advisory（标注、不记账、不自动改正式结构）；判据预注册入档案，措辞零概率宣称|BC-001 在新功能上的落点|
|BC-110|桌面运行如实告知：自动模式要求开奖时段 harness 处于运行状态——此约束必须出现在开启引导，不得以任何文案暗示「后台永远在跑」|桌面 harness 非 7×24 的物理事实；反虚假宣传|

### 2.3 数据约束（增量）

|编号|类别|逻辑名称|描述|
|-|-|-|-|
|DC-101|实体|渠道配置|type（qq/panel/webhook/社区自定义…）、enabled、per-channel 凭证字段（schema 由适配器声明）；存放于用户本地配置；面板展示一律脱敏|
|DC-102|实体|通知事件|kind、级别、时效线、正文（按详略档渲染）、状态（待发/重试/已送达/补发队列/失败可见）；事件层持久化，语义对齐 FR-005|
|DC-103|实体|角色配置|角色类型（数据官/策略师/质询者/主持人）、实例数、任务提示词、版本号；策略师可克隆；版本 stamp 进预测档案|
|DC-104|值域|预算与权重|周度总预算（默认 1,500,000）；类别分项；每角色权重（默认 1.0）与绝对值覆盖（注入上限默认 4000、调用上限）；判定沿用 DC-011 周度口径|
|DC-105|值域|力度档|枚举：follow-host/economy/standard/turbo；映射规则（参数直传或轮数杠杆）随模型能力探测，stamp 进档案|
|DC-106|值域|投注结构档|每彩种合法结构档表（含注数与每期价格），档位 = 用户配置；基线自动同构（DC-002 继承）|
|DC-107|值域|输出详略档|枚举：concise/chatty；作用于推送渲染，不影响档案全文（DC-001 继承）|
|DC-108|实体|技巧卡片|沿用 docs/12 DC-003（含信任级：用户上传文件默认「中」）+ preprocessor 清洗标记（是否剥图/去噪）与入库状态|
|DC-109|值域|数据底座状态|每彩种：全量回填进度、最新期号、连续性校验结果、最后校验时间；探针判据沿用 FR-008（>7 天 ✗）|
