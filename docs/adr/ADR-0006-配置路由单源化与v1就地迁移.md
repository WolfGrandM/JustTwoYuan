# ADR-0006 配置路由单源化与 v1 配置就地迁移

- 状态：已采纳（v0.2 B3 / T-11 施工前置）
- 日期：2026-10-26

## 背景

`docs/15:147 FR-1020` 与 `docs/10 §5.1` 要求「面板 / 配置文件 / CLI」三个配置入口等价。实际实现里有两个读法：

- `lib/config.js:readConfig()`：默认值 + 用户文件，且对 **v1 遗留配置**（有 `games`、无 `modes`）按 `games.<k>.enabled` 换算三态（true→auto / false→off / 缺省→manual）。scheduler 与 CLI 用它。
- `lib/index.js` 的 `/api/config` 路由：`{ ...buildConfigDefaults(), ...readJson(...) }` 浅合并，**不做 v1 换算**。

由此产生两个真实缺口：

1. **读不等价**：v1 遗留配置下，面板 GET 返回的 `config` 缺 `modes`，而调度器实际按换算后的 modes 运行——面板显示与真实运行状态不一致。
2. **写路径死锁**：同场景下面板 POST 因 `modes` 缺失被 `validateConfig` 拒绝（`modes 缺失`），**永远不落盘**。用户无法从面板完成迁移，只能改用 CLI `migrate-v2`。

## 候选方案

| 方案 | 内容 | 取舍 |
| --- | --- | --- |
| A | 维持现状，只登记为已知差异 | 三入口不等价永久存在；面板对 v1 用户功能性失效 |
| B | GET/POST 统一走 `readConfig` | 读面：GET 多出 `modes`（加法字段）；写面：v1 配置首次 POST 即写回换算后的 v2 配置（就地迁移） |
| C | 统一读，但 POST 仍走旧写路径 | 读等价了，写仍拒绝；缺口 2 未解 |

## 决策

采用 **B**。

1. `/api/config` 的 GET 与 POST 统一调用 `readConfig(CONFIG_FILE)`，与 scheduler / CLI 同源。
2. 接受两处行为变化，均只发生在 **v1 遗留配置**（`!user.modes && user.games`）：
   - GET 响应多出换算后的 `modes`（FZ-6 语义为「只增字段」，安全）；
   - POST 校验通过后把合并结果写回配置文件，等效于**首次面板 POST 就地完成 v1→v2 迁移**。
3. v2 配置（已有 `modes`）下，`readConfig` 与旧浅合并等价，GET/POST 行为逐位不变。
4. 不新增路由、不改任何既有响应字段名与状态码；`_说明` 仍只在首写模板中存在，运行时读不引入。

## 后果

- 正面：三入口真正等价（FR-1020 收口）；v1 用户不必碰 CLI 就能迁移；面板显示与调度器运行态一致。
- 代价/风险：
  - v1 配置首次 POST 会把完整合并结果写回文件（含用户文件里的未知字段，如作者实例的 `push` 段）——**保数据不丢**，但文件形态从 v1 变为 v2。已登记的 `migrate-v2` 仍是显式迁移通道，二者幂等不冲突。
  - 写回发生在用户点「保存」时，不是后台自动改写；不存在静默迁移。
- 验收：新增 v1 fixture 测试（GET 含换算 modes、POST 落盘且二次 GET 为 v2 形状）＋既有 v2 配置测试全绿；`docs/decisions/v0.2-B3-默认决策记录.md` 记录本决策编号。
- 冻结区：不触碰 FZ-1~5/FZ-7；FZ-6 只增字段。
