## §2 模块与接口设计

### 2.1 落位裁决：`lib/mind/` 子目录（而非单文件）

**选子目录**，理由四点：① 四个正交关注点（编排/注入/裁剪/计量 + 议程）单文件会重演 scheduler.js 千行混合体的 v0.2 审计问题（docs/22 §3 T-05 动机）；② 测试文件认领需要稳定的模块边界（docs/28 §7 先例：每测试套件对应一模块交付面）；③ 与 lib/review/ 先例同构（M4 已验证该组织方式可实施）；④ **不建独立插件**——市场版单插件谱系（docs/28 §0）下独立插件意味着跨插件契约复活，与 ADR-9 的市场版消解结论冲突。目录内文件互不 re-export，依赖单向（§2.2）。

### 3.3 两级降档关系：会话级 25 分钟链 vs 周级 BC-013 链（谁先触发谁生效、互不覆盖）

两级链**正交且都生效**：会话级链作用于「阵容维度 castTier」（本次出号内降档），周级链作用于「力度/预算维度 effortTier + cap」（跨期持续降档）。语义矩阵：

| 周级状态（demotionFor，usage.js:95-104） | 会话级 25 分钟链 | 生效语义 |
| --- | --- | --- |
| ok / warn1（<70% / 70-90%） | 正常起跑 | 生效阵容 = planTier（满配解锁判定后）；warn1 仅预警推送，档位不动 |
| warn2（90-100%） | 正常起跑 | effort 降一档（力度维度，既有）；**castTier 不受影响**——两级互不覆盖：预算压力收敛到「力度降档+分项预警」，阵容保持计划档 |
| cap（≥100%，allowLLM=false） | **不起跑** | 兜底档直接出号零 LLM（scheduler.js:322-328 既有行为零改动）——周级 cap 短路优先于一切会话级编排；复盘/学习类暂停既有语义不变 |
| 任意 | 切片超时 | castTier 逐级下降（仅本期内生效），effortTier 保持周级状态；两 stamp 各记其面（条目 effortTier=周级、castTier=会话级终态），归因分段读两个 stamp（DC-010 精神） |

「谁先触发谁生效」的单点裁决：**cap 短路 > 硬停线 > 切片超时降档 > 计划档**——四级优先序在 orchestrator 入口一次性判定（`resolveTier()` 纯函数），中途只降不升（本期内不回升；下一期按新预算状态重新判定）。降档事件推送面：周级降档/触顶事件随 T4 预警段统一交付（§5.4）；会话级降档记 stamp + 周报健康节「降级次数」统计口径扩展读 castTier 序列（既有读 effortTier 序列并列保留——两维度分开计数）。

## §4 议程与数据衔接

### 4.1 dataPack 注入段 = 数据官/策略师的标准输入材料

数据官 prompt 的「研究材料」段 = `dataPack(gameKey, history, { tailCount: lever.tail, issue })` 输出**原文**（scheduler.js:980 成本估算同源实测面）——即收尾批 T1 已上线的「近 N 期流水 + 遗漏/频次表 + 相似局势 top-3 + 当前局势分位行」（stats.js:121-168）与 M3 编排共用同一数据源与同一防前视双保险（similar 切片严格早于目标期 stats.js:49-53 + insightBlock 最低在库期数门 stats.js:27）。分层清晰不重复注入：

| 层 | 来源 | 进哪个角色 | 上限 |
| --- | --- | --- | --- |
| 数据层 | stats.js `dataPack`（官方开奖统计 + 探索性素材段） | 数据官（全文）→ 数据官数据包引用行传递给策略师/主持人 | 数据官切片内自然收敛（材料即任务） |
| 记忆层 | injector blocks（因子战绩 + 近 30 期档案局势） | 按角色差异化：数据官/主持人全量（≤4000/角色）、策略师各 ≤4000（trimmer 整块丢弃） | FR-030：单角色 ≤4000、standard 档期合计 ≤16000 |
| 议程层 | agenda 渲染（角色任务提示词 + 纪律声明） | 全角色 | 提示词定长（模板常量+用户覆盖段≤2000 字符校验） |

BC-004 引用链：策略师/主持人「引用材料行」只允许引用数据层与记忆层已注入的行（prompt 明示「引用行编号」），主持人定稿引用清单经 injector 校验（引用行不在注入集 → 打回）——防幻觉引用与 BC-004 观察纪律在产出面的闭环。

### 4.2 环 A 提案因子（candidate）进博弈的引用规则

环 A 收尾批 T2 已建立「月报提案 → factor_proposals 表 + 因子库 candidate 态（零特权）」（proposal.js:94-178）。M3 博弈层的引用规则单点裁决：

- **observing/promoted 才可引用**：injector 因子块过滤 `status IN ('observing','promoted')`（§2.2）——提案因子完成 candidate→observing 入观察（monthly.js runPipeline ⓪ 既有边）后才进博弈观察路径。
- **candidate 只在提案段展示**：candidate 因子的唯一曝光面 = 月报探索性提案段（monthly.js 既有）+ /api/review 因子库状态——**不进任何出号会话注入、不进博弈材料、不进推送**。
- **零特权贯通**：博弈对提案因子的引用若发生（observing 后），其战绩照走归因引擎与月报检验，无任何加权旁路（proposal.js:10-12 零特权纪律的 M3 延伸）。
- 3d 无 DSL 表达面如实延续（proposal.js:14-15 PROPOSAL_GAMES 不含 3d）——3d 的博弈注入记忆层只有局势块无因子块，不虚构。

### 4.3 auto-memory 剥离监听器（Spike2 方案落地，FR-028/AC-022）

机制（Spike 记录 §2.5 推荐实现原样落纸）：koi 插件注册 `system-prompt/assemble` waterfall 监听器（宿主先例 dsh-working-directory/lib/index.js:48-60）：

```
ctx.on('system-prompt/assemble', async (assembly, context, next) => {
  const out = await next()                     // 返回值权威（dsh-system-prompt/lib/index.js:398-405）
  if (isKoiDrawSession(context.agent)) {       // AssembleContext.agent 增广（runtime-types.d.ts:14-19）
    out.sections = out.sections.filter(s => s.name !== 'memory:index')   // 段名常量 MEMORY_SECTION（auto-memory src/prompt.ts:23）
  }
  return out
})
```

- **出号会话判定** = `context.agent?.session.id` 匹配 `koi-daily-<game>-<issue>` 前缀（§2.6 会话 id 规范）——比 cwd 判定更精确且零新增配置；koi-lottery 闲聊会话不匹配 → 不剥离（FR-028「koi-lottery 闲聊会话不受此限」原文）。
- **监听器挂载时机** = koi 插件构造期（T3）；`mind.enabled=false` 时监听器仍挂载（出号会话照常新开、剥离照常生效——宿主注入与认知层开关是两件事，出号会话**任何形态下**都不吃宿主级注入，AC-022 断言不随开关摆动）。
- **工具级整合不破坏**：memory_write/read/list/delete 四工具全局保留（Spike §2.5「备选 A 不取」的理由——工具剥离即违反 FR-028 整合要求）。
- **段名耦合防线**（Spike 开放问题①）：段名 `'memory:index'` 单点常量 + T3 交付一并落 AC-022 断言「出号会话 system prompt 不含 memory:index 渲染产物」+ 运行手册检查项「dsh-auto-memory 升级后重跑剥离断言」——插件版本锁定（docs/06 §9 版本耦合代价条）。
- **认知层主动喂入（每期档案摘要 → memory_write）延后 v0.3+**：FR-028 前半句「喂入内容由认知层按模板决定」本批只交付注入侧收口；喂入侧依赖出号会话 agent 的工具可用性验证，列 §9-R6。

### 4.4 注入失败语义（FR-031）

injector.assemble 任何异常/空库 → `{ blocks: [], ok: false, note: '本期无记忆注入：<原因>' }` → orchestrator 照常编排（记忆层为空不阻塞）→ 条目 stamp `injectionNote`；单期不推送；连续 ≥2 期（per 彩种）→ health.js 触发器③告警（FR-033/§2.5）。宿主级注入剥离失败（H4 不达）**不等同**注入失败——前者是「出号会话多吃了宿主注入」的违纪面（AC-022 检查项 + T3 启动自检 log 告警），后者是「认知层没喂进材料」的降级面（FR-031 语义）；两条分开计数、分开上报。
