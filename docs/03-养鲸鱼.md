## 图形界面（推荐，不用敲命令）

设置页是网页版的，挂在你自己的 DSH Web 界面里，位置是 **设置 → 养鱼**。

### 最省事：双击 `打开鲸鱼面板.cmd`

工作区根目录里那个脚本会自己做完三件事：建隧道 → 取 token → 开浏览器。关掉那个最小化的隧道窗口就等于断开。

### 手动三步

**第 1 步：开隧道**（Windows PowerShell，窗口别关）

```powershell
ssh -i "D:\QQ工作区\_deepseekharness.pem" -N -L 3080:127.0.0.1:3080 root@120.55.184.195
```

> 本地 3080 被占了就换一个：`-L 13080:127.0.0.1:3080`，后面地址里的端口一起改。
> 报 `UNPROTECTED PRIVATE KEY FILE` / `bad permissions` 是 Windows 的私钥权限太宽，修法见下面「排障」。

**第 2 步：拿带 token 的地址**（服务器上，或另一个终端）

```bash
ssh -i "D:\QQ工作区\_deepseekharness.pem" root@120.55.184.195 dsh-url
# http://127.0.0.1:3080/?token=xxxx
```

**第 3 步：浏览器打开那个地址 → 左下角「设置」→ 左侧选「养鱼」**

> ⚠️ 「养鱼」**不在**左下角「…」那个菜单里 —— 那个菜单只有 设置 / 意见反馈 / 登录。
> 要先点「设置」打开设置面板，它是面板里的**一个分组**（排在靠后，可能要往下滚）。

页面上分七组：


| 分组 | 有什么 |
| --- | --- |
| 凭据 | SESSDATA / bili_jct / buvid3 三个输入框 + 「写入凭据」（写入后永不回显） |
| 她是谁 | 角色名、她怎么称呼你、她怎么自称、人设正文（写完点「注入人设」） |
| 你（主人） | 主人 mid、主人昵称；她自己的 mid/昵称只读（来自 cookie 与 nav） |
| 口味 | 爱看 / 不爱看（逗号分隔） |
| 作息 | 作息窗口（可加多个）、**今晚不看的概率**、单次看的视频数、最小唤醒间隔 |
| 日记与推送 | 推送日记摘要、主人 @ 请求总结、消息推送方式 |
| 工具链 | 专用会话目录、工具目录 |

两个容易踩的点：

- **改完必须点「保存」** —— 输入框是先改在本地，点保存才落盘；不点等于没改。
- **「依赖体检」会先自动保存再测**，它真的会请求一次 B站 验证登录态，并检查 ffmpeg / Node / 数据目录。

> 隧道断了（合盖、换网）就重跑第 1 步；服务重启后 token 会变，重跑第 2 步。

## 命令行（等价，适合脚本/远程）

下面几步是纯命令行版本，改的是同一份配置文件，和界面做的事完全一样。

## 第 1 步：填 cookie

1. 浏览器登录 <https://www.bilibili.com>。
2. `F12` → **Application（应用）** → **Cookies** → `https://www.bilibili.com`。
3. 抄三个值：`SESSDATA`、`bili_jct`、`buvid3`（`buvid3` 可以留空，前两个必须）。
4. 在设置页「养鱼 → 凭据」粘贴，点**保存**。

> ⚠️ 别用 `document.cookie` 取 —— `SESSDATA` 是 HttpOnly，脚本读不到，最后会得到一份缺件的 cookie，卡在体检。
> ⚠️ 两个值必须来自**同一个账号、同一次登录**，否则写操作会回 `-111 CSRF 校验失败`。

也可以直接在服务器上写文件（把三个值换成你的）：

```bash
sudo -u dsh tee /home/dsh/.bili-ai/credentials.json > /dev/null <<'JSON'
{"sessdata":"…","bili_jct":"…","buvid3":"…"}
JSON
chmod 600 /home/dsh/.bili-ai/credentials.json
```

## 第 2 步：填主人 mid 和昵称

`mid` 是你 B站 空间的数字 ID（空间地址 `space.bilibili.com/12345678` 里那串）。写进配置的 `owner`：

```bash
sudo -u dsh nano /home/dsh/.dsh/bili-whale.config.json
# "owner": { "mid": "12345678", "name": "你的昵称" }
```

`name` 是评论正文里 @ 出来的字，写错就 @ 不到人；改完可以用 `thread` 复核 `@到:` 那一行。

## 第 3 步：写人设（可选）

```bash
sudo -u dsh mkdir -p /home/dsh/.bili-ai
sudo -u dsh nano /home/dsh/.bili-ai/persona.md
```

只取**前 3000 字**，建议顺序：我是谁 → 说话 → 我在意什么 → 我绝不会 → 日记怎么写 / 分享标准。

## 第 4 步：验收

```bash
sudo -u dsh -H bash -lc "cd /opt/dsh-plugins/dsh-bili-whale && node tools/bili.mjs deps"
```

期望：**每一项都是 ✓**。只剩 cookie 一项红的话，就是第 1 步没做对。

再看凭据属于哪个号（写操作前必跑）：

```bash
sudo -u dsh -H bash -lc "cd /opt/dsh-plugins/dsh-bili-whale && node tools/bili.mjs session"
```

## 第 5 步：让她立刻醒一次

现在作息是每天 **20:00–24:00** 随机一个时刻醒一次，而且有 30% 概率「今天不想看」。

想立刻看一轮：改配置把窗口设成「现在之后 2 分钟」的一小段，保存即生效（不用重启）：

```bash
sudo -u dsh nano /home/dsh/.dsh/bili-whale.config.json
# "night": { "windows": [ { "start": "12:40", "end": "12:50", "wakes": 1 } ] }
```

她醒来会：体检 → 选题 → 看懂 → 写两本日记（你一本、她一本）→ 挑 2–3 条 @ 你。全程不用你说话。

改完记得把窗口改回 20:00–24:00。

## 关于完全访问权限（重要）

鲸鱼要写的两个地方都在会话工作目录之外：

- 日记 → `~/.dsh/whale-diary.md`
- 凭据 / 额度账本 → `~/.bili-ai/`

DSH 默认的 `workspace-write` 沙箱只允许写会话 cwd（`~/.dsh/whale-work`），所以她一写日记就会被拒。
这台机器是专用机、只监听 `127.0.0.1`、只有你能进，所以直接把默认模式放到 `danger-full-access`：

```bash
grep DSH_PERMISSION_MODE /etc/dsh/dsh.env
# DSH_PERMISSION_MODE=danger-full-access
systemctl restart dsh     # 改环境变量必须重启；改鲸鱼配置不用
```

副作用：**这台机器上所有新会话都是完全访问**（无人工审批）。如果以后要在这台机器上跑别的不信任的活，就把这行删掉、重启，再在 Web 界面里单独给她那个会话开权限。

## 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `UNPROTECTED PRIVATE KEY FILE` / `bad permissions` | Windows 的私钥默认继承目录 ACL，被 OpenSSH 判定"别人也能读" | `icacls "D:\QQ工作区\_deepseekharness.pem" /inheritance:r /grant:r "你的用户名:(R)"`（Git Bash 的 ssh 不校验权限，所以同一把 key 在那里能用、在 PowerShell 里报错） |
| 设置面板里找不到「养鱼」 | 看的是本地桌面版（没装插件），或没点进「设置」 | 确认地址栏是 `127.0.0.1:3080`（隧道），再点「设置」；「…」菜单里没有它 |
| 体检说 cookie 红 | 没填 / 文件权限不对 | 重填一次，`chmod 600` |
| 只读命令全好、写命令报 `-101` | SESSDATA 过期 | 重新登录 B站 抄一次 |
| 写命令报 `-111` | `bili_jct` 和 `SESSDATA` 不是同一个号 | 两个一起重抄 |
| 她醒了但什么都没做 | 撞上 30% 跳过 / 不在窗口内 | `night status` 看今天计划 |
| 写日记报权限错误 | 沙箱还是 workspace-write | 检查 `DSH_PERMISSION_MODE`，重启 |
| 改了设置页不生效 | 没点「保存」 | 输入框是先改在本地，点保存才落盘 |
| 换插件版本后行为没变 | bundle 层要重启才重组 | `systemctl restart dsh` |

## 卸载

```bash
sudo -u dsh -H bash -lc "dsh plugin --profile web remove dsh-bili-whale"
systemctl restart dsh
# 数据要一起清：rm -rf /home/dsh/.bili-ai /home/dsh/.dsh/whale-*
```
