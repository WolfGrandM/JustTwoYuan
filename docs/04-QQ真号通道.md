# 04 · QQ 真号通道（NapCat + dsh-onebot）

用**自己的 QQ 号**在群里聊天，不是官方机器人身份。走的是 OneBot 11 协议：NapCat 假装成 QQ 客户端登录你的账号，dsh 通过 WebSocket 收发消息。

> ⚠️ 这条路违反 QQ 用户协议，腾讯按「异常登录/异常行为」处置。最轻是掉线要重扫，最重是封号。用空闲号，别用主号。

## 现在的样子

| 项 | 值 |
| --- | --- |
| QQ 号 | 983605373（昵称 `I'm just a bot`） |
| 所在群 | 96414936「沉睡森林公会」（245 人） |
| 触发 | 群里被 **@ 或回复她的消息** 才开口 |
| 管理员 | 1017099872（🌱大灰狼外婆）—— 能私聊、能用斜杠命令 |
| 群策略 | 白名单，只放行 96414936 |
| 模型 | deepseek-flash（默认） |
| 工作目录 | `/home/dsh/workspace` |

## 架构

```
QQ 群友
  ↕ (QQ 协议)
NapCat（Docker 容器，跑 QQ 客户端）
  ↕ OneBot 11 WebSocket  ws://127.0.0.1:3001
dsh-onebot 插件（跑在 dsh 进程里）
  ↕ 每个会话一个 agent
DeepSeek 模型
```

两段连接都在 `127.0.0.1` 上，公网看不到。

## 组件与路径

| 东西 | 位置 |
| --- | --- |
| NapCat 容器 | `napcat`，镜像 `mlikiowa/napcat-docker:latest` |
| 容器端口 | `127.0.0.1:3000`（HTTP API）、`3001`（OneBot WS）、`6099`（WebUI） |
| 登录态 | `/opt/napcat/qq` → 容器 `/app/.config/QQ` |
| NapCat 配置 | `/opt/napcat/config` → 容器 `/app/napcat/config` |
| OneBot 配置 | `/opt/napcat/config/onebot11_983605373.json` |
| 登录看板 | `http://127.0.0.1:8099/`（`napcat-qr-web.service`） |
| 二维码同步 | `napcat-qr-sync.service`，每 2 秒把容器里的码拷到 `/opt/napcat/live/` |
| dsh 插件 | `dsh-onebot-qq` 0.9.4，配置在 `profiles/web/cordis.patch.yml` 的 `dsh-onebot` 条目 |

## 容器怎么起的（关键：`ACCOUNT`）

```bash
docker run -d --name napcat --restart=always \
  -e NAPCAT_UID=0 -e NAPCAT_GID=0 -e TZ=Asia/Shanghai \
  -e ACCOUNT=983605373 \
  -p 127.0.0.1:3000:3000 -p 127.0.0.1:3001:3001 -p 127.0.0.1:6099:6099 \
  -v /opt/napcat/qq:/app/.config/QQ \
  -v /opt/napcat/config:/app/napcat/config \
  mlikiowa/napcat-docker:latest
```

**`ACCOUNT` 不能省**。不带的后果：容器一重启就退回「扫码登录」，缓存的登录态白费。带上它日志里会出现「正在快速登录 983605373」，重启服务器也能自己恢复。

## 群策略与触发

| 配置 | 值 | 含义 |
| --- | --- | --- |
| `requireMention` | `true` | 群里必须 @ 或回复她 |
| `groupPolicy` | `allowlist` | 只认白名单里的群 |
| `groupAllowFrom` | `['96414936']` | 白名单 |
| `dmPolicy` | `open` | 私聊只对管理员开放 |
| `adminUsers` | `['1017099872']` | 管理员 |
| `rateLimitPerMinute` | 20 | 每会话每分钟上限 |
| `interimMessages` | `false` | 只发最终回复，不发中间态 |

想放开某个群：往 `groupAllowFrom` 里加群号。想让别人也能私聊：加进 `adminUsers`。改完自动热重载，不用重启进程。

## 常用运维

```bash
# 她在线吗（期望看到 OneBot connected）
journalctl -u dsh -n 50 --no-pager | grep onebot

# 看她收到什么、回完没有
journalctl -u dsh -f | grep -E "followup|turn/end"

# 她在哪些群
curl -s -X POST http://127.0.0.1:3000/get_group_list -H 'Content-Type: application/json' -d '{}'

# 登录态还在吗
curl -s -X POST http://127.0.0.1:3000/get_login_info -H 'Content-Type: application/json' -d '{}'

# 重启协议端（不会丢登录态，因为有 ACCOUNT）
docker restart napcat

# 换一张登录二维码（掉线时）
curl -s -X POST http://127.0.0.1:8099/refresh
```

## 掉线了怎么办

症状：群里 @ 她不回；`docker logs napcat` 出现「请扫描下面的二维码」。

1. 双击 `打开鲸鱼面板.cmd`（隧道 3080 / 6099 / 8099）
2. 打开 `http://127.0.0.1:8099/`
3. 点「换一张」→ 倒计时回到 120 秒 → 手机 QQ（983605373）扫
4. 手机点「确认登录」
5. 等 1 分钟，`journalctl -u dsh` 里出现 `OneBot connected` 就好了

如果扫码后报错 **168**（账号存在安全风险），说明触发了腾讯风控：需要在手机上登录这个号，按提示完成短信/人脸验证，**验证通过后再扫一次**。缓存的票据在验证前是作废的。

## 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `ECONNRESET` / `socket hang up` 每 60 秒一次 | NapCat 的 OneBot WS 没开（`websocketServers: []`） | 编辑 `onebot11_983605373.json` 加 ws server，`docker restart napcat` |
| 重启后要重新扫码 | 容器没带 `ACCOUNT` | 按上面命令重建容器 |
| 她只回一句就没了 | 非管理员带 `[受限用户:仅问答]` 软限制 | 把对方 QQ 加进 `adminUsers` |
| 群里 @ 她不回 | 群不在白名单 / `requireMention` 判定 | 加群号；确认是「@她」或「回复她」而不是纯文本提到 |
| 收到图她只看到 `[图片]` | `vision.enabled` 默认关 | 要好看图得挂视觉模型（额外 key），否则只能读文字 |
| `/status` 秒回但不进日志 | 斜杠命令由插件本地处理，不经过模型 | 正常现象 |

## 安全边界

- 三个端口全绑 `127.0.0.1`，只能走 SSH 隧道
- `3000` 的 HTTP API **没有设 token**，因为它只对本机开放；哪天要暴露到别的机器，必须先加 `token`
- 她跑在 `danger-full-access` 下（全局 `DSH_PERMISSION_MODE`），能读写服务器文件。这是为了让鲸鱼能写日记，代价是她也能动别的东西
- 账号是空闲号，不要在号上绑支付、不要用它登录重要服务
