# ADR-0004 账本：诚实记账（模拟口径 + 三态条目 + append-only 更正）

- 状态：已采纳（v1.1 修复包定型；市场版随投注档位制扩展）
- 日期：2026-10-25 回填入档

## 背景

「诚实记账」是产品根命题（docs/05 立项即定：账本难看是功能不是 bug）。v1 曾有 BUG-K1（放弃分支漏记成本）——v1.1 修复时把账本语义一并定型。

## 决策

1. **唯一口径**：ledger 只记「每期正式预测都买」的模拟账；加餐/手动推荐/组选和值分析永不入账（BC-006）。投入按当期实际投注结构（市场版档位制）记。
2. **三态条目**：放弃待补（23:30 后官方未公布：记成本、prize 空）、补判（公布后追加 supplement 条目，cost 0）、休市作废（官方证实期号不存在：追加冲销 reversal）——全部走 **append-only**：更正 = 追加条目 + 指向原条目指针，永不改写（BC-002）。
3. **carry 全量扫描**：跨天顺延扫描所有未结清条目（!settled 或 given-up，排除 voided），多日宕机不漏账。
4. **判奖引擎冻结**（FZ-1）：judge/enumerateBets/comb 只读复用；市场版档位判奖 = 拆单元逐判聚合（tiers.judgeTier），判奖语义零改动；金样本回归 12 例守门。
5. 战绩永远连同随机基线上报（DC-002 同构基线）；浮动奖当晚按 0 计注数照报。

## 后果

- 正面：口径唯一、可审计（更正可追溯）、崩溃/宕机不漏账。
- 代价：append-only 使「改错」略绕（必须追加而非编辑）——这是防自欺的刻意代价。
- 实测：v1.1 上线首两期即诚实入账（投 44 中 0）。
