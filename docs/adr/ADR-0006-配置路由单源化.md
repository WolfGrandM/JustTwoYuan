# ADR-0006 配置路由单源化（面板读写与调度器同源）

- 状态：已采纳（v0.2 B3 / T-11 施工前置；2026-10-26 Gate 2 后修订事实前提）
- 日期：2026-10-26

## 背景

`docs/15:147 FR-1020` 与 `docs/10 §5.1` 要求「面板 / 配置文件 / CLI」三个配置入口等价。实际实现有两个读法：

- `lib/config.js:readConfig()`：默认值 + 用户文件，且对 **v1 遗留配置**（有 `games`、无 `modes`）按 `games.<k>.enabled` 换算三态（true→auto / false→off / 缺省→manual）。scheduler 与 CLI 用它。
- `lib/index.js` 的 `/api/config` 路由：`{ ...buildConfigDefaults(), ...readJson(...) }` 浅合并，**不做 v1 换算**。

`buildConfigDefaults()` 自带 `modes`（全 manual），因此旧实现的实际缺陷不是「缺字段被拒」，而是两处**静默语义偏差**：

1. **读偏差**：v1 遗留配置下，面板 GET 返回的 `modes` 恒为默认 `manual`，而调度器实际按 `games.enabled` 换算成 auto/off 运行——面板显示与真实运行态不一致。
2. **写偏差**：同场景下面板 POST 能通过校验（`modes` 来自默认值），但写回的是**默认 manual modes + 原 `schemaVersion: 1`**——v1 的 auto/off 语义在文件里被悄悄抹成 manual；好在版本号仍为 1，事后 `koi.mjs migrate-v2` 仍能按 `games` 正确补回。

（早前版本的本 ADR 曾把缺陷描述为「modes 缺失导致 POST 被拒、写路径死锁」，该描述与实测不符，Gate 2 已纠。此处以可复现命令为准：`{...buildConfigDefaults(), ...v1}` 过 `validateConfig` 返回 `ok:true`。）

## 候选方案

| 方案 | 内容 | 取舍 |
| --- | --- | --- |
| A | 维持现状，只登记差异 | 三入口不等价永久存在；面板每次保存都在抹掉 v1 语义 |
| B | GET/POST 统一走 `readConfig`，写回时**升** `schemaVersion` | 会造出「v2 标记 + v1 残留」混合文件：`migrate-v2` 以 `schemaVersion===2` 短路，push 侧车 / v1 等价档 / gates 永不迁移——**已在 Gate 2 实测证伪，否决** |
| C | GET/POST 统一走 `readConfig`，写回**保留原 `schemaVersion`** | 读面与运行态一致；写面不再抹掉 auto/off；`migrate-v2` 仍能完整迁移（版本号未变）——采用 |
| D | v1 配置直接拒绝面板写入，提示跑 CLI | 语义最干净，但 v1 用户面板完全不可编辑 |

## 决策

采用 **C**。

1. `/api/config` 的 GET 与 POST 统一调用 `readConfig(CONFIG_FILE)`，与 scheduler / CLI 同源。
2. **GET**：v1 遗留配置返回换算后的 `modes`（auto/off/manual），与调度器运行态一致；v2 配置行为逐位不变。
3. **POST**：同样以换算结果为基线做 patch、校验、原子写；**不修改 `schemaVersion`**。因此 v1 文件写回后仍是 `schemaVersion: 1`，`games` 段保留，`migrate-v2` 的完整迁移通道原样可用。
4. **面板保存不是迁移通道**：push 凭证迁侧车、v1 等价档（`v1EquivTier`）、`gates.honestyAck`/`wizardDone` 这些只由 `koi.mjs migrate-v2` 完成；本 ADR 不声称「就地完成迁移」，只保证「面板读写不再损坏语义」。
5. 不新增路由、不改任何既有响应字段名与状态码。

## 后果

- 正面：三入口**读**面等价（FR-1020 核心）；面板保存不再把 v1 的 auto/off 悄悄改成 manual；`migrate-v2` 仍可一次跑完剩余迁移。
- 代价/风险：
  - v1 文件在面板保存后会同时含 `games` 与 `modes`（后者为换算结果）；运行态以 `modes` 为准，`migrate-v2` 之后会以 `games` 重算并删除 `games`——两套口径在迁移完成前并存，属可接受过渡态。
  - 若用户永远不跑 `migrate-v2`，文件长期停在 v1 标记 + 双段并存；不会丢数据，但 push 凭证不会自动迁侧车。
- 验收：`tests/market-config-route.test.mjs` 覆盖 v1 GET 换算、v1 POST 保留版本号与 `games`、v2 零差异、非法 patch 不落盘、坏配置（`null`）兜底。
- 冻结区：不触碰 FZ-1~5/FZ-7；FZ-6 只增字段（GET 的 `modes`）。
