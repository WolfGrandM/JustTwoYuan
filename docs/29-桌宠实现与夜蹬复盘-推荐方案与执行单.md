2. **回环 API 冒烟**（服务器本机执行，FZ-4 回环围栏内）：

```bash
# 状态出口可达（GET /state 为唯一状态出口，API.md「state 详解」节）
curl -s http://127.0.0.1:3080/dsh-pet-7340/state | head -c 300
# 锁-投喂-释放全链路冒烟（ADR-0007 §2 决策 2 的桥接动作序列预演）
# 取锁：POST /lock?pet= 回 lockId + expiresAt（API.md「二、占用锁」表；v1.1.0 补可复制实参）
RESP=$(curl -s -X POST 'http://127.0.0.1:3080/dsh-pet-7340/lock?pet=main')
LOCK=$(printf '%s' "$RESP" | jq -r '.lockId // .data.lockId // empty' 2>/dev/null)   # 有 jq 时优先
[ -n "$LOCK" ] || LOCK=$(printf '%s' "$RESP" | sed -n 's/.*"lockId"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p')   # 无 jq 的 sed 兜底
echo "lockId=$LOCK"    # 人工核对非空——空 = 取锁失败，停，先看 $RESP 原文
curl -s -X POST "http://127.0.0.1:3080/dsh-pet-7340/broadcast?pet=main&lock=$LOCK" -d '{"text":"锦鲤桥接冒烟"}'
curl -s -X POST "http://127.0.0.1:3080/dsh-pet-7340/lock/release?pet=main&lock=$LOCK"
```

   判据：broadcast 后浏览器宠物气泡出现「锦鲤桥接冒烟」；锁占用期宠物静止、释放后恢复（API.md:28「锁占用期间桌宠完全静止」）。⚠ 实际 pet id（默认 `main`）、lock 响应包裹层级（顶层 `lockId` 或 `data.lockId`）与 JSON 字段名以装件时 `/config` 实查为准——两条提取路径都留了，取空即人工看 `$RESP` 原文补一条适配，不得瞎猜字段名硬跑。
