### 2.3 主循环（run）——分批、限速、断点、退避、错峰

```text
run(game, { smoke = false } = {}):
  0 作业互斥（BC-012「任一时刻至多一个后台作业」的市场版落点，W2A-20）：acquire 作业锁
    koi/job-lock.json {kind,key,at,heartbeatAt}（kind ∈ backfill|ingest|backtest，三者互斥）
    被占 → { ok:false, error:'另一后台作业进行中（<kind>/<key>），完成后重试' }；
    每批更新 heartbeatAt；正常结束/中止即释放；心跳停更 >30 分钟视为残留锁可抢占并留痕
  1 错峰守卫（BC-012，first-wave 语义沿用）：cfg.backfill.offpeakOnly（默认 true）且 now ∈ [17:00, 22:30)
    → 不启动，返回 { ok:false, error:'错峰窗口（17:00–22:30）内不执行全量回拉，22:30 后再试或用 --no-offpeak 显式越过' }
  2 已在拉（同 game，进程内）→ 409 语义 { ok:false, error:'正在拉取中' }
  3 续拉起点（断点续传）：
      ssq：oldest = 库内最早期号（drawstore 新增加法导出 oldest(game)——读 entries 首条，升序存语义下 O(1)）；
           无库 → 先 ensureRecent(game, 30) 铺底（复用第一波机制，30 期内含最新）
           windowEnd = oldest - 1；若 windowEnd 落入「本年不存在区」（windowEnd < yearOf(windowEnd)*1000+1，
           即跨年边界：windowEnd ≡ xxx000）→ 跨年步进：windowEnd = (year-1)*1000 + 400（年中探针值，
           区间语义下多要的不存在期号会被源端自然裁掉——冒烟实测 F：区间只返回实际存在的期号）
      dlt/p3：nextPageNo = checkpoint.nextPageNo ?? 1（页界天然连续，冒烟实测）
  4 循环（smoke=true 时最多 2 页/彩种，仅用于管线自验）：
      批首三查（PM 复核意见1 补）：stopped（stop() 置位 → 当前批完成后退出，断点保留，§2.5 暴露到 CLI/面板）
               / 错峰复检（运行中跨入 17:00–22:30 → 暂停：checkpoint 保留 + status='paused-offpeak'，
                 22:30 后自动续拉——与 ingest「停 queued 等窗口」同款语义；防 16:35 启动的 15–30 分钟
                 回拉跑进禁算窗，仅查启动时刻的旧设计已废）
               / 锁心跳更新（job-lock.heartbeatAt = now）
      page = 按 mode 组参数 → fetchPage(game, page)          // 1 次请求
      空页 → done（§2.4）；targetIssues 达成 → done（提前收口）
      v = validateDraws(game, page)（第一波四项校验，BC-104）→ store.upsertBatch(game, v.valid)
      rejected 累计入 checkpoint.rejectedTotal（留痕：期号+原因也追加进 koi/draws-rejected.log 一行一条，
        追加写、不覆盖——审计面，防「拒了什么」随 checkpoint 覆盖丢失）
      ssq：windowEnd = 本页最早期号 - 1（同跨年步进规则）
      checkpoint 原子写（含 requests++ / fetchedIssues += page.length / progress）
      sleep(cfg.backfill.batchGapMs 默认 2000)               // 批间限速（礼貌：秒级间隔）
  5 单批失败退避：重试 3 次，间隔 2s / 8s / 30s（指数 + 抖动上限）；3 败后：
      ssq → 窗口减半（batch 界内收窄，最小 10）再试一轮；仍败 → 中止（checkpoint 保留，重启续拉）
      dlt/p3 → pageSize 不可降（源端上限语义），直接中止保留断点
      中止信息写 checkpoint.lastErr（面板/CLI 可见，S-111 语义：拒用并留痕，不静默）
  6 页界连续性防御（跨批）：新页最早期号必须早于库内现存最早期号（按开奖日期比较）；检出重叠/倒挂
    → 记 checkpoint.gapNote 并继续（upsert 幂等去重兜底；完整审计由 §3 全库扫描收口）
```

### 2.4 done 判据与进度（MB-30 沿用 + 实测校正）

- **done = 空页**（ssq：期号窗口返回 0 条=早于上市；dlt/p3：pageNo 返回空 list）**或 targetIssues 收口**。窗口/页码是确定性地址而非游标，空页语义可靠（冒烟实测支撑）。
- 防御：连续 3 个空窗（ssq 跨年步进可能先遇空年段）→ 判 done 并在 audit 标注 `stoppedAtEmptyStreak`。
- 进度分母：全量模式下 targetIssues 未知 → 分母用「进度就绪值」= 首批返回时按源端可得的最早上市期号估算常量（`EARLIEST_ISSUE = { ssq: '2003001', dlt: '07001', p3: '04001' }` 常量表 + 库内实际期号差校正）；面板进度条显示「已拉至 <最早期号>（N 期在库）」**而非百分比**（分母是估计值，百分比会伪精确——诚实显示，W2A-08）。
- done 后自动触发 §3 全库审计，结果写 checkpoint.audit + `backbone status` 透出。

## §4 ② 学习入库半环 — FR-1013/1014/1015、DC-108、S-107/118/119

### 4.1 上传入口（三通道；面板为主——Gemba 结论）

### 4.2 格式支持的现实裁决（FR-1013 收窄——W2A-04，回流项）

**首发仅 TXT/MD（含强转 MD）；PDF/EPUB 显式标注「暂不支持」并列待办。** 理由：

1. 项目零外部依赖红线（docs/17 §6-7）：PDF/EPUB 解析无一等内置方案（node 内置无 PDF/EPUB 解析器），引第三方库（pdf-parse/pdfjs、epub 库）须评估体积/供应链，与「倾向不新增」相悖；

3. 诚实拒收优于半吊子解析：415 响应与面板提示均明示「支持 .txt/.md；PDF/EPUB 请先转为文本（暂不支持直接解析，已在待办）」。

```text
     "computable":true|false,"dupOf":null|"card-…既有id","similarTo":null|"card-…既有id"}]}
硬性规则：
  · 只拆「针对具体彩种开奖号码的选号技巧」；作者闲谈/心态建议 → 不成卡（宁缺毋滥）；
  · rule 必须是文本中真实存在的表述（可轻度压缩，不得引入文本外知识）；
  · dupOf/similarTo 只能填上面清单里的 id，别的值一律按 null 处理会被校验拒收；
  · 与既有卡完全同义 → dupOf 指它（不重复入库）；相近但条件不同（如区间不同）→ similarTo；
  · 写完文件就收工：不要发任何消息、不要动这个文件之外的东西。
```

- 交卷校验（代码侧）：schema 校验（字段/类型/games 合法/dupOf 白名单）不过 → **一次打回重写**（同出号流水线姿势）→ 仍不过 → `pending-llm`（S-119）；打回与重试都如实记 job.error。
- 无模型（classifyHostError 命中 no-model）→ job 直接 `rejected`（错误=配置指引文案，FR-1022），**不进 pending-llm**（配不出来永远待补是死等，清晰失败更诚实）。

## §5 ③ 回测引擎框架 — FR-039/FR-040 市场版落点、AC-012/023 适配

### 5.1 因子注册接口（lib/backtest.js）

```js
/**
 * 因子 = 纯函数对象（注册制）。引擎保证防前视：predict 收到的 history 恒为「截至 asOf 期（含）」
 * 的切片（升序），因子不可能读到未来（AC-012 的结构性保证，非提示词约束）。
 * factor = {
 *   id: 'builtin-sum-band-ssq',     // 全局唯一（内置前缀 builtin- / 卡片前缀 card-）
 *   source: 'builtin' | 'card:<cardId>',
 *   game: 'ssq',
 *   name: '和值区间',
 *   /** 预注册命中判据（DC-004：因子化时定死）——claim 人读 + judge 代码判 */
 *   predict: (historyAscending) => ({ claim: '下一期红球和值将落在 90–130', judge: (next) => ({ hit: next.sum>=90&&next.sum<=130, detail: '和值=107' }) }) | null   // null = 本期无观点（跳过该轮）
 * }
 */
export function createBacktest({ cardsStore, drawStore, factors = [], now, log })
→ { register(factor), runBuiltin({game}), runFactor(factorId), runCard(cardId), verdicts(game), fileOf }
```

### 5.2 滚动回测循环

```text
runFactor(factor, { warmup = cfg.backtest.warmup 默认 30 }):
  entries = drawStore 全库升序（drawstore.getRecent(game, Infinity) 全量切片）
  rounds = 0, hits = 0
  for t in [warmup .. entries.length-2]:          // 留最后一期作被预测期；每轮预测 t+1
    p = factor.predict(entries[0..t])             // 切片传入（防前视由引擎保证）
    if p == null → skip（无观点轮不计入分母——如实分开计：rounds / skips）
    r = p.judge(entries[t+1]);  rounds++;  hits += r.hit ? 1 : 0
  baselineRate = 判据滞后自评满足率 = Σ_t judge_t(entries[t]) / rounds
    （对每轮 t，用该轮判据去判「判据形成时点本身的那期」——对自适应判据（如滚动 μ±σ）良定义，
     且因判据含该期形成、对基线略偏乐观 → 对「优于随机」的宣告偏保守，方向正确）
  pValue = 单侧精确二项检验 P(X ≥ hits | n=rounds, p=baselineRate)（对数乘积防溢出）
  verdict = pValue < α(0.05) ? 'better-in-sample' : 'no-advantage'
  return { factorId, game, rounds, skips, hits, hitRate, baselineRate, pValue, verdict, ranAt }
```

- 运行约束：与 backfill/ingest 共用作业锁（§4.4-0，W2A-20；CLI 直跑 `backtest run` 同样 acquire）；`entries.length - warmup < cfg.backtest.minRounds（默认 100）` → 拒跑并明示「本地历史不足 N 期（先全量回拉）」——样本不足不出结论（advisory「样本不足」同款诚实姿势）。
- 错峰（BC-012）：纯计算单因子全库 O(N)（N≈数千，毫秒级）——本波六内置因子 + 少量卡片因子远够不成「重计算」，但守卫照挂（cfg.backtest.offpeakOnly 默认 true；`--no-offpeak` 显式越过），纪律优先。

### 5.3 统计口径与「与随机无异」（W2-D05）

- verdict 文案档（**离散档，禁百分比置信度**——BC-007 同精神）：`better-in-sample`（样本内优于随机基线，附 p 值与样本量）/ `no-advantage`（**与随机无异**——预期默认，如实入档）。
- 多重检验披露：一次 run 全家（六内置 + 全部卡片因子）跑完，报告头恒拼「本轮共检验 K 个因子，α=0.05 下期望约 K×0.05 个因子纯因偶然过关；单因子『样本内优于随机』不构成采用建议」。**不做 Bonferroni 强校正**（样本内结论本就不用于决策——§5.8 边界），披露优先。
- 口径披露（每份结论恒附）：「基线 = 判据滞后自评满足率（每轮判据回判其形成期）；检验 = 单侧精确二项；样本 = 本地全量历史 N 期滚动回测；命中判据在回测前预注册（因子定义即判据）」。
