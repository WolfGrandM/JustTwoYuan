# ADR-0002 调度器：宿主进程内 30s tick 状态机

- 状态：已采纳（v1 起；市场版扩为每彩种三态模式门控）
- 日期：2026-10-25 回填入档

## 背景

插件需要每日定时（出号 17:30、对账 22:00 起）驱动业务，且要跑在用户自己的 harness 里（web/desktop 双 profile）。候选：独立常驻进程 / cron / 宿主进程内定时器。

## 决策

1. **形态**：宿主 Node 进程内 `setInterval` 30s tick + 全状态落盘（state.json）——重启从盘上恢复续跑，不依赖任何外部调度器。
2. **窗口语义**：出号段（每彩种独立 predictAt，默认 17:30；补跑窗口至 catchUpEnd 19:50）；对账段（settleAt 22:00 起，15 分钟/轮 × 8 轮；放弃线 23:30）；休市日历命中则全天静默顺延（BC-011）。
3. **三态模式门控**（市场版）：每彩种 off/manual/auto——off/manual 跳出号流水线（「现在来一注」基础层除外，它永远可用）；**对账不受模式门控**（账本诚实优先：已出的号必对账）。
4. **错峰窗口**：17:00–22:30 禁重计算（全量回拉/回测），后台作业单飞锁互斥排队。
5. **桌面形态如实告知**：桌面 harness 非 7×24，自动模式要求开奖时段应用在运行（写进开启引导，BC-110）。

## 后果

- 正面：零外部依赖、双 profile 同构、崩溃恢复强。
- 代价：应用不开机就不 tick（物理事实，已用补跑窗口+如实文案缓解）；30s 粒度意味着配置热生效延迟 ≤30s。
- 关键教训：状态机的相位语义是 FZ-5 冻结区，改相位转移需走解冻流程（见 ADR-0005）。
