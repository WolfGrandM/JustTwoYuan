# ADR-0005 冻结区与「改造不重写」

- 状态：已采纳（v1.1 轮定型 FZ-1~6；市场版新增 FZ-7）
- 日期：2026-10-25 回填入档

## 背景

主人 2026-10-24 定调「改造不重写」：v1 代码稚嫩但作为 SDD 流程输入保留改造，不做推倒重写。需要一套机制防止多轮迭代把既有语义改漂。

## 决策

1. **冻结区清单**（语义不变，非代码不变——允许重构内部，不许改行为）：
   - FZ-1 判奖（judge/enumerateBets/stakesOf/comb）
   - FZ-2 产出校验（validatePicks/randomPicks）
   - FZ-3 三 JSON 既有字段语义与路径（只加字段）
   - FZ-4 NapCat 回环断言（市场版泛化为信任栅栏 fail-closed）
   - FZ-5 状态机相位与转移（carry 扫描范围扩属已登记解冻）
   - FZ-6 面板 API 请求/响应形状（只增字段）
   - FZ-7 角色围栏（市场版）：用户可配角色数量/任务提示词，硬校验/基线/归因/推送契约/兜底标注在围栏外结构锁定
2. **解冻流程**：确需动冻结区 → 显式登记（哪个区/为什么/影响面）→ 版本 minor+1 → 走结构轨评审——没有静默解冻。
3. **市场包卫生**：物理不含 qq 适配器与 QQ 配置字段、零作者凭证、零作者默认值；hygiene 工具自动检查（AC-102）。
4. 配套纪律：全量测试基线只增不减；浏览器加载链路（exports→roster→combo）无本地测试，部署后必开一次面板。

## 后果

- 正面：三轮迭代（v1.1/市场版/第二波）零语义漂移，回归全靠冻结区+测试基线兜住；重构（v0.2 迭代）有了明确护栏——冻结区外的屎山可以治，冻结区内的行为不许变。
- 代价：有时「顺手改」要升格走流程——刻意的摩擦。
