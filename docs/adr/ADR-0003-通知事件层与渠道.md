# ADR-0003 通知：事件层 + 可插拔渠道适配器

- 状态：已采纳（市场版重构落地；v1 的 NapCat 直推语义已迁移）
- 日期：2026-10-25 回填入档

## 背景

v1 把 QQ 私聊（NapCat HTTP）硬编码为唯一通知通道——与「市场版零 QQ、用户自带凭证」冲突（BC-103），且重试/补发/心跳语义与通道耦合。

## 决策

1. **事件层唯一出口**：所有出站通知先成为结构化事件（kind/级别/时效线/正文/状态），FR-005 的统一重试（5 分钟间隔）、分类终止线、补发队列（上限 20、同类合并、溢出告警）、心跳语义全部下沉到事件层实现一次——渠道适配器只做传输。
2. **适配器契约**：声明 type / 配置 schema / send(event)；核心从渠道目录发现加载；注册但缺适配器文件 → 清晰配置错误（不崩溃）。内置：panel（桌宠小组件渠道）；作者私有：qq.js（NapCat，不进市场包）；社区扩展接口即同一契约。
3. **心跳泛化**：自动模式彩种今日应有通知在全部启用渠道均无送达记录 → 红标；恢复后自动补发并清除。
4. **打扰策略**（主人 2026-10-25 拍板）：桌宠红点/冒泡/面板未读**只统计中奖战果**（won===true）——非中奖事件静默入列表，随查随看。
5. 事件持久化于 koi/events.json（补发队列唯一事实源；state.json 旧 repushQueue 字段停写容忍读）。

## 后果

- 正面：加渠道零业务改动；市场版与作者实例共用核心；测试事件独立类别（test）不伪装告警。
- 代价：一次间接层（事件→渲染→渠道）；旧字段兼容读取。
- 已知边界：渠道送达回执只有 panel/qq 类同步接口可靠，webhook 类以发出为准（第二波待办）。
