# 20 · dsh-koi 插件开发管线

> 本文是流程文档，不是需求/设计文档（那些在 docs/14–19）。它回答「一个改动从想法到上线走什么路」。本文由编排会话按主人指示落盘（2026-10-25），源头是两天的实战沉淀与主人 SDD 工具链会话的指示。

## 1. 需求讨论模式（入口）

- **协作方式**：主人给大致想法与拍板，AI 负责细化技术方案；AI 逐需求补关键缺口（解决什么/预期形态/约束/完成标准），每个缺口带推荐项。
- **总确认表收尾**：需求聊完后输出一张表（已锁定项 + 待批推荐项 + 待办池），主人回复「全按推荐」或逐行改——这是从讨论进入执行的闸门。
- **待办池**：细节模糊或素材缺失的需求不硬做，入池登记种子（docs/14 §五先例），成熟一个拉一个。

## 2. 双轨变更流

改动按量级分流，**不许混轨**：

| 轨道 | 适用 | 流程 | 落盘 |
|------|------|------|------|
| **结构轨（大改）** | 新能力/架构性改动/多模块联动 | 四阶段管线：A 设计定稿（aet-req-analysis/design 精神）→ 独立产品经理复核（退回修订回路）→ B 实施与自测 → 独立验收门 | 新 docs/NN 文档 + docs/decisions/<轮次>-{A,B} 决策记录 |
| **直修轨（体验迭代）** | bug 修复 + 需求小改动 | 主人报 → AI 直接修 → 全量测试零回退 → 主人重启实机验证 → PM 定期润色 | docs/18 迭代变更记录（TF 条目，四要素） |

**升格规则**：直修轨的改动若实质长成新能力，明说升格走结构轨（RR→IR→SDD→确认书），不允许默默吸收。

**现成的管线模板**：动态工作流已参数化保存（`.zcode/workflows/dwfrun-aa0abbc6-….dwf.ts`，CreateWorkflow `saved:` 按名运行；模型/文档路径/测试门均可传参）。两波实战（v1.1 修复包、市场版两轮）均由它跑通。

## 3. 质量门（所有改动的硬约束）

1. **全量测试门**：`<DSH-runtime-node> --test plugins/dsh-koi/tests/*.test.mjs`（本机无全局 node，用 `~/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/node/bin/node.exe`；**必须 glob 形式**，传目录在该 node v24 下会失败）。当前基线 209 项，只增不减。
2. **冻结区**：FZ-1（判奖）/FZ-2（校验）/FZ-3（三 JSON 语义）/FZ-4（回环断言）/FZ-5（状态机相位；carry 解冻需登记）/FZ-6（面板 API 只增字段）/FZ-7（角色围栏——用户可配「怎么想」，不可配「纪律怎么算」）。
3. **市场包卫生门**：`node tools/hygiene.mjs`——零 QQ 痕迹、零作者凭证、零作者默认值（BC-101/103、NFR-102）。
4. **诚实条款**：任何文案零概率宣称；「最好/有效」类结论必须预注册判据 + 回测支撑；兜底/加餐/补发/基线缺失标注恒在。
5. **每改动必落盘**：直修轨记 docs/18（TF 条目）；结构轨记决策记录——没有「先改了以后再补文档」。

## 4. 部署会话流程（作者实例 = 市场包 + 私有 qq 适配器）

1. 本地：全量测试门全绿 → `scp -i <pem> -r plugins/dsh-koi root@<host>:/opt/dsh-plugins/dsh-koi`
2. 服务器：`sed -i 's/\r$//' lib/*.js tools/*.mjs`（去 Windows 换行符）→ 配置检查（`/home/dsh/.dsh/koi.config.json`，升级用 migrate 工具）→ `dsh plugin --profile web add 'link:…'`（已装则跳过）→ `systemctl restart dsh`
3. 验证：journalctl 见「锦鲤生物钟已启动」→ `koi.mjs deps` 全✓ → `koi.mjs selftest` 全 pass → 面板/桌宠实机
4. 五步验收（首次部署）：测试通知 → 来一注 → 当晚对账+ledger → 杀 NapCat 跑一期（补发）→ 对账中途重启（不重复记账）
5. **注意事项**：面板 UI 的浏览器加载链路（exports→roster→combo）无本地测试覆盖，部署后必开一次面板；web 前端模块清单来自配置树 dsh.client 行，别往 profile cordis.patch.yml 里补 UI insert。

## 6. ADR（架构决策记录）

重大既有决策以 ADR 入档（现状回填，非新决策）：`docs/adr/ADR-0001~0005`（数据源/调度/通知事件层/账本诚实/冻结区与改造不重写）。新架构决策照此格式追加，编号递增不回收。

## 7. v0.2 迭代规划位：重构（未启动）

主人定调（2026-10-25，源自 SDD 工具链会话指示）：**不发起「重构运动」，把重构定义为 v0.2 迭代**。动机：项目管线当时没有架构师角色，多轮直修后存在屎山化风险。方案待主人从其工具链会话贴入后在此补全；先决条件：v0.1（市场版+第二波）实机验证收口、全部改动 commit 入库。重构期间的护栏：冻结区不动、测试基线不减、每步小 PR 粒度（建议）。
