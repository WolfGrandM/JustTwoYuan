## 2. 集成点清单

### INT-1 · DSH 插件生命周期
| 项 | 契约 |
| --- | --- |
| 挂载声明 | `cordis.patch.yml`：`id` 与 `name` 都必须是包名 `dsh-koi`，不一致表现为「装上了但面板 404」（已写入清单注释） |
| 入口 | `package.json` `main: lib/index.js`，default export `{ name, inject, apply(ctx) }` |
| 依赖注入 | `inject: ['sessionController', 'webServer', 'connection']` —— 宿主按名供给；缺哪个，用到哪个的功能直接不可用（调度器 tick 会因无 sessionController 空转） |
| 清理 | `ctx.effect(() => () => {...})`：停调度器 timer、注销全部路由 —— 宿主卸载/重载插件不泄漏 |

### INT-2 · sessionController（唤醒锦鲤）
| 项 | 契约 |
| --- | --- |
| 建会话 | `ctx.sessionController.create({ sessionId: 'koi-lottery', cwd: workDir })`，失败（已存在）静默沿用 |
| 提问 | `prompt({ requestId: 'koi-<ts>-<rand>', sessionId, mode: 'queue', content }, AbortController.signal)` —— **mode:'queue' 是关键**：await 返回即本轮跑完，天然串行 |
| 失败语义 | prompt 抛错 = 本次尝试失败 → 计 attempts；会话历史跨天保留（⚠ 上下文增长 → N5） |
| v2 预留 | 记忆注入 = 在 `buildPredictPrompt` 里加段，不碰 sessionController 用法 |

### INT-3 · webServer 路由 + 信任栅栏
| 项 | 契约 |
| --- | --- |
| 注册 | `ctx.webServer.register({ kind: 'exact', path, handler })`，4 条路由前缀 `/dsh-koi/api/*` |
| 安全 | 每个 handler 先过 `isLoopbackReq`（Host 头须回环）再过 `connection.requestRejection`（宿主信任栅栏）；任一不可用 → 503 **fail-closed**（宁可不可用不裸奔） |
| 错误 | handler 抛错统一 500 `{ok:false,error}`；body 上限 16KB |

### INT-4 · 面板 slots（client 半边）
| 项 | 契约 |
| --- | --- |
| 注入 | `slots.inject('settings.section', register({ id:'koi', order:7, label:'彩票' }, KoiSection))` |
| 数据 | 仅消费自家 4 条 API，30s 轮询 status，加餐 4s 轮询 job |
| 不碰别人 | 不读鲸鱼/onebot 的任何路由与状态；人设文案里「别串台」只是嘴上的 |

### INT-5 · NapCat HTTP API
| 项 | 契约 |
| --- | --- |
| 用到的端点 | `POST /send_private_msg {user_id, message}`、`POST /get_login_info`（体检/面板探测） |
| 安全 | 基址强制回环（`assertLoopback` 抛错）—— 3000 端口无 token，这个断言是安全不变量（冻结区 FZ-4） |
| 失败语义 | 10s 超时；`retcode===0 || status==='ok'` = 成功；失败返回 `{ok:false, word}` 交调度器重试 |
| 与 onebot 插件分工 | onebot 管「收消息→起会话」，koi 管「主动私聊发送」——互不改一行代码。若未来 onebot 提供发送 API，可评估切换，当前不做 |

### INT-6 · 官方数据 API
| 项 | 契约 |
| --- | --- |
| 双色球 | `findDrawNotice?name=ssq&issueCount=N`，头：UA+Referer+Accept；GBK 按 utf8 解析（数字字段全 ASCII）；返回含 `prizegrades` → 对账直接用 |
| 体彩 | `getHistoryPageListV1.qry?gameNo=85|350133`，头必须带 Referer/Origin/UA 否则回验证页；`lastPoolDraw.prizeLevelList` 解析奖级（跳过追加行） |
| 排列三口径 | 排列五开奖号前三位（3501xx 段无排列三独立 gameNo，实测确认） |
| 失败语义 | 15s 超时/HTTP 非 200 → 抛错 → 出号计失败重试、对账下轮再试；`deps` 可一键验活 |

### INT-7 · 文件系统布局
| 路径 | 归属 | 说明 |
| --- | --- | --- |
| `$DSH_HOME/koi.config.json`（`KOI_CONFIG` 可覆盖） | 配置 | 首跑自动落默认；每 tick 现读 |
| `$DSH_HOME/koi/{state,predictions,ledger}.json` | 数据 | 契约见 docs/10 §5.1；**koi 独占写** |
| `$DSH_HOME/koi-work/` | 会话目录 | 会话 koi-lottery 的 cwd；`predict-<game>-<date>.json` 文件契约的交换场 |
| 与鲸鱼同约定 | — | `DSH_HOME 优先，兜底 ~/.dsh`，两插件路径互不重叠 |

### INT-8 · systemd / journald
`console.log('[koi] …')` → `journalctl -u dsh`；过滤约定 `grep koi`；崩溃由 systemd 5 秒拉起，状态从盘上恢复（FR-10）。

### INT-9 · 与鲸鱼插件共存
同款路径约定、同款信任栅栏姿势、同款「生物钟 tick」模式（鲸鱼 60s / 锦鲤 30s）；会话各自独立（koi-lottery / 鲸鱼自己的）；互不注入对方 slots。

### INT-10 · （v2）dsh-koi-mind 认知层
- 形态：**独立插件**，对 koi 的三 JSON **只读**；自持 SQLite（koi-mind 独占写）。
- 所有权矩阵（防止双写互踩，契约级集成的核心）：

| 文件/库 | koi | koi-mind | tools CLI |
| --- | --- | --- | --- |
| state.json | 读写 | — | 只读 |
| predictions.json | 读写 | **只读** | 读写（settle，v1.1 起原子写） |
| ledger.json | 读写 | **只读** | 读写（settle/ledger --reset） |
| koi.db（SQLite） | — | 读写 | （v2 加只读查询命令） |
| koi-work/ 会话目录 | 调度器清写 | — | — |

### INT-11 · （v2）记忆插件（Q3，建议 auto-memory）
工具级整合：装上即全局可用；**喂什么**由 koi-mind 决定（每期档案摘要、复盘结论按模板写入 memory_add），注入时机跟随 17:30 唤醒提示词。两个记忆插件不可同装（注入冲突）。

### INT-12 · （v2）dsh-web-search（Q8）
工具级整合，零代码；站点白名单与提取纪律由 koi-mind 的学习任务提示词约束。

## 3. 部署集成流程

继承 docs/05 的部署节（scp → 去 CRLF → `dsh plugin --profile web add link:` → restart dsh → 验收）。v1.1 起两点修订：

1. `sed -i 's/\r$//'` 范围从 `lib/*.js` 扩为 `lib/*.js tools/*.mjs`（C7）；
2. 验收从三步扩为五步：原三步 + 「杀 NapCat 跑一期验证未送达语义」+「对账中途 `systemctl restart dsh` 验证恢复不重复记账」。

回退：`dsh plugin --profile web remove` + restart，数据目录保留不动（卸载不删账）。
